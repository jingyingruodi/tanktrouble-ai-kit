# 11 · 前端改版适配：从 GWT 全局到 ES Module 私有作用域

> 2026-10-16 发现并修复。本文记录**网站前端改版导致整套自动化失效**的经过、根因与修复方案，
> 以及新环境下必须遵守的运维约束。

## 1. 现象：一觉醒来全部 API 消失

隔了 13 天回到项目，页面能正常打开（主菜单、"1/2/3 players"、Classic 模式都在，
页脚仍是 `RELEASE-2026-08-31-01`），但：

```
window.GameManager / ClientManager / Users / Constants / Inputs / OverlayManager / TankTrouble
   → 全部 undefined（ReferenceError: ClientManager is not defined）
```

而页面加载的脚本已换：

```
https://tanktrouble.com/build/js/libraries-843e34fa.js
https://tanktrouble.com/build/js/index-4YALVKHK.js     ← 新的打包产物
```

## 2. 根因：同一份 GWT 代码被重新打包成 `<script type="module">`

* HTML 里是 **`<script type="module" src="/build/js/index-4YALVKHK.js">`**；
* 包内代码仍是那套 GWT 客户端（`getGameController`×27、`setInputState`×6、`createNewGame`×6、
  `quickjoinGame`×2 都在），但类被 **压缩 + 变成 ES6 `class`**（如
  `var Ze=class s{static client=null;static clientId="";…new Ne("ClientManager")}`）；
* **模块顶层绑定是私有的**：既不挂 window，也不进全局词法环境 → 外部 eval 拿不到。
  （只有 `window.KnockKnock`（彩蛋函数）和 `window.location` 是显式的 window 赋值。）
* 属性/方法名**没有**被压缩（`static guestUsers`、`phaserInstance`、`pushOverlay`、`setInputState` 都在），
  所以只要能把类对象捞出来，**老工具代码基本可原样运行**。

## 3. 修复：CDP `Fetch` 拦截 + 包尾"自发现"补丁

工具：`scripts/patch_frontend_api.py`

1. 本地取到 bundle 文本，按正则提取**候选标识符**：
   * `var/let/const X = class …`
   * `class X …`
   * `X = { Prop: … }`（命名空间对象）
   * `X.NewGameOverlay = …` 这类"先建对象再挂属性"的写法（★ 新前端的 `TankTrouble` 就是这种，
     它在包里叫 `M`）
2. 在 bundle **尾部追加**一段补丁：在**模块作用域内**用 `eval(name)` 逐个取出候选值，
   按"静态字段/原型方法特征"识别成各类，再 `window.<Name> = …` 与 `window.__TT`；
   同时导出 `window.__TT_ALL`（296 个类）与 `window.__TT_MSG`（**按 typeId 汇总的 60 个消息类**）。
3. 用 CDP `Fetch.enable` 拦截该 module 请求，`Fetch.fulfillRequest` 回填**打过补丁的包**，
   然后 `Page.reload` → 页面里老 API 全部复活。

识别用两套签名（`SIG` 静态字段、`CSIG` 原型方法、`NSIG` 命名空间对象）：

| 目标 | 判定特征 |
|------|---------|
| `ClientManager` | `static client` + `static clientId` |
| `GameManager` | `static phaserInstance` / `static getGameController` |
| `Users` | `static guestUsers` + `static authenticatedUsers` |
| `Constants` | `static GAME_MODES` + `MAZE_TILE_SIZE`/`SERVER` |
| `Inputs` | `static inputManagers` / `_assignInput` |
| `OverlayManager` | `static pushOverlay` |
| `TankTrouble` | 对象含 `NewGameOverlay`（包里变量名 `M`） |
| `UIUtils` | 静态 `mpx` |
| `B2DUtils` | 静态 `calculateProjectilePath` |
| `UIAimerGraphics` | 原型 `addPoint` |
| `PremiumManager` | 静态 `isPremiumPresent` |
| **`InputState`** | **原型有 `getForward`/`getBack`/`getLeft`/`getRight`/`getFire`** |

### ★ 踩过的坑：`withState` 有多个同名类

包里至少 4 个类都有静态 `withState`（`InputState` 6 参、`TankState` 10 参、以及
`zs`/`qi`/`mn`/`Qi` 等 GWT 状态类）。第一版补丁用 `typeof c.withState === 'function'` 判定，
**先撞上了 8 参的那个**，于是：

```js
InputState.withState(pid, fwd, back, left, right, fire)   // 老代码
→ 落到 (id, playerId, type, x, y, speedX, speedY, fieldsJSON) 签名上
→ setInputState 收到错误的载荷 → 坦克一动不动（控制校验位移 0.00m）
```

**必须按原型方法判定**（实例有 `getForward/getFire` 才是按键版）。修正后
`InputState.withState.length === 6` ✅，控制校验恢复（位移 1.93m）。

同时给 `Inputs` 加了兼容别名 `Inputs.__metaclass = Inputs`，老代码里的
`Inputs.__metaclass.inputManagers` / `._playerIdInputSetId` 不用改。

## 4. 运维约束（重要）

* **补丁靠 Fetch 拦截生效**，所以：
  * 必须让 `scripts/patch_frontend_api.py auto --keep-open` **常驻运行**，它会对**每一次**页面加载
    持续回填补丁包（早期版本只回填第一次，导致后续刷新页面卡在"没有游戏代码"的状态）；
  * 该进程退出后，**新开的页面加载就没有补丁**（已加载的页面不受影响）。
* 页面刷新后引导是自动的（拦截在加载时生效），但**别绕过 Fetch 直接缓存**（补丁响应带 `no-store`）。
* 核对工具：`scripts/toolkit_probe.py`（逐项体检我们依赖的 API，改版后可第一时间发现问题）。

## 6. 结论

* 客户端**没有重写**，只是**重新打包 + 作用域私有化**；属性名保留是我们能快速修复的关键；
* 修复是**非侵入式**的：不改游戏代码、不 hook 游戏方法，只在传输层回填一份"多了一行导出"的包；
* 老工具链（监控室、火控、录制、在线沙箱、弹道模块）**无需大改**即可继续用。

## 7. 适配过程中额外踩到的两个坑（2026-10-16）

### 7.1 `Box2D` 不再是全局 → 火控推演崩

修复 API 后跑火控验收，崩在：

```
ReferenceError: Box2D is not defined
  at Object.GetPosition (<anonymous>)         ← 我们构造的假弹丸体
  at s.calculateProjectilePath (index-4YALVKHK.js)
```

根因：`tank_behavior_template._raycast_path` 的 JS 片段用
`Box2D.Common.Math.b2Vec2.Make(x, y)` 造位置/速度向量，而**新前端不再把 Box2D 暴露成全局**。

修法（不依赖任何全局、与库版本无关）：**从游戏自己的 b2Vec2 实例派生**——

```js
const _v0 = tank.getB2DBody().GetPosition();
const _vproto = Object.getPrototypeOf(_v0);
const mkVec = (x, y) => { const v = Object.create(_vproto); v.x = x; v.y = y; return v; };
```

`GetPosition`/`GetLinearVelocity` 改用 `mkVec(...)` 后，`find_aim_angle_raycast` 恢复正常
（实测 `max_bounces=4` 与 `25` 都能算出命中角）。

### 7.2 老脚本的端口参数是"数字"，传 `auto` 会被静默当成 9222

`scripts/fire_verify_strict.py`、`record_only.py` 这类**上个 agent 留下的老脚本**
用的是 `int(args[0]) if args[0].isdigit() else 9222`，传字符串 `auto` 会退回 9222
（那个实例可能已死）→ `urlopen timeout`。

**约定**：老脚本一律传**解析后的数字端口**（`resolve_port('auto')` 的结果）；
新脚本（`start_online_game.py` / `start_local_game.py` / `measure_*` / `fire_burst.py` / `verify_*`）支持 `auto`。

### 7.3 本地验收需要"先创角色"

`fire_verify_strict.py` 需要**两个可控坦克**（角色 `arrows` + `keyboard`）。
如果 `Users.getAllPlayerIds()` 只有 1 个 id，本地局会配一个机器人，
验收脚本会报 `缺少角色: arrows=None`。做法与在线一致：**先在 Menu 调 `_twoPlayer()` 创角色，再开本地局**。
