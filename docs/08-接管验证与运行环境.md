## 3. 运行环境：dsh-ego-browser（本项目新的默认自动化浏览器）

### 3.1 为什么改用它

* 它是 **Edge + 持久 profile** 的常驻单例浏览器，**不会被后台冻结**
  （旧方案里 Edge 冻结/睡眠标签页 → 游戏暂停 → 监控掉帧、脚本假死）。
* 它由 DSH 插件托管，窗口/焦点状态稳定；实测**对 Phaser 菜单的点击有效**，
  而直接对自带 Edge 窗口发裸 `Input.dispatchMouseEvent` 点不动菜单（焦点/冻结导致）。
* 登录态持久化在磁盘，可用 `ego_login_import` 从系统浏览器导入 cookie。

### 3.2 端口是动态的（关键）

ego 浏览器以 `--remote-debugging-port=0` 启动，**真实端口由系统分配**，写在：

```
%LOCALAPPDATA%\ego-lite-linux\browser.json
{"port":51109, "wsUrl":"ws://127.0.0.1:51109/devtools/browser/...",
 "pid":25780, "binary":"...msedge.exe", "headless":false, "profileDir":"..."}
```

因此**不要把端口硬编码**。本轮新增 `cdp_tools/ego_browser.py`：

| 函数 | 作用 |
|------|------|
| `resolve_port(value)` | `None`/`'auto'`/端口 → 真实可用端口（ego 优先，回退扫描 9222-9231），失败抛 `RuntimeError` |
| `discover(preferred)` | 详细结果 `{port, source:'ego'\|'edge'\|'explicit', browser, pid, profile_dir, pages, game_page, error}` |
| `list_pages(port)` / `find_game_page(port)` | 列页面 / 找游戏页 |
| `python cdp_tools/ego_browser.py` | 自检并打印来源与页面 |

**端口参数现在到处都可以写 `auto`**：

```powershell
python tt.py ping auto
python tt.py local 2 auto
python monitor_server.py 1 auto --tm 0
python scripts/start_local_game.py auto --players 2
```

自带 Edge（9222+）仍是超集内的合法取值，`auto` 在 ego 不可用时自动回退扫描。

## 4. 自动开 Local 局 + 角色绑定（`scripts/start_local_game.py`）

### 4.1 它解决的坑（务必知悉）

程序化开一局 Local game 后，`window.Inputs.__metaclass.inputManagers` 是**空数组**：
input set（`WASDKeys` / `arrowKeys` / `mouse`）没有分配给任何 `playerId`。后果：

* `get_roles()` → `{}`；`pick_role()` → `None` → 所有控制脚本报"没有可控坦克"；
* `setInputState` 无法把本地输入与坦克对应起来。

按真实按键、等重生都不会自动补上（实测无效）。**必须显式绑定**：

```js
Inputs._assignInput(playerId, inputSetId)   // 与 UI 选择控制方式走同一函数
```

### 4.2 用法

```powershell
python scripts/start_local_game.py                # auto 端口、2 人局、绑定 arrows+WASD
python scripts/start_local_game.py --players 3    # 3 人局（+ mouse）
python scripts/start_local_game.py --restart      # 先刷新页面再开局（干净复现）
python scripts/start_local_game.py --json         # 机器可读输出
python tt.py local 2 auto                         # 等价快捷入口
```

作为库：

```python
from start_local_game import ensure_local_game
info = await ensure_local_game('auto', players=2)
# info = {port, players, bind, pids, roles, actions, model, inputSets, maze}
```

流程：`Menu →(菜单处理器 _onePlayer/_twoPlayer/_threePlayer) Lobby
→(localGameButton 处理器 _createLocalGame) 对局 → 绑定 input set → 校验角色`。
幂等：已绑定的玩家不会重复绑定（`action='already'`），并防止同一 input set 绑给两人。

> 说明：调用的是**游戏自己的 UI 处理器**（等价于点按钮），不是 hook/替换 GWT 方法，
> 因此不触碰"红线"（见 `07-会话交接.md` §9.2）。

### 30 回合验收：v4 失败 → 根因 → 修复 → v5 复跑

* **v4**（`scripts/fire_strict_v4.jsonl`，611 帧）：第 2 回合失败，日志报"回合有命中角但未击杀"。
* **取证**（离线解析录制）：攻击者 t=30.5s 开火，弹丸 `deadlyToOwner=True` 飞出 13.7m 后折返，
  距离 12.7→3.7→**1.8m**，t=32.6s 攻击者消失 → **自伤**（不是"没打中"）。
  该角是 62m / 3 次反弹的长路径，预测自伤检查（4.0m）放行。
* **修复**：见上表 #13/#14/#15。
* **v5**：`4.0+1.0×反弹数`（上限 8.0）→ 无自伤，但 10 回合里 6 回合"找不到角"（跳过率 60%，v3 仅 ~14%）。
* **v6**：`4.0+0.5×反弹数`（上限 6.0）+ 飞行上限 45m → 前 11 回合通过，**第 12 回合自伤**（新诊断正确报出"攻击者死亡 → 意外自杀"）。
* **v7**：**恢复 v3 已验证的选角默认值**（固定自伤半径 4.0、轴线命中判定、不兜底），
  仅保留 `max_traveled=45` → ✅ **30/30 回合全部有击杀、无自伤**（28362 帧，41 个迷宫
  版本 ≈ 11 次无解跳过，跳过率 ~27%）。**项目火控已回到并重新确认合格状态。**
* **结论**：改动已验证的选角逻辑必须重新验收；我的安全改动全部保留为默认关闭的
  可选参数，默认行为回到 v3 基线并再次通过验收。
* **v8（运行中）**：开启**炮口出膛建模**（`--muzzle 2.0`）做对比轮次——真实弹丸从炮口
  出膛而推演从车体中心出发，这个起点偏移是多反弹路径"预测安全、真实自伤/打偏"的
  主要误差源。若 v8 通过且跳过率下降，则把该模型转正。

**⚠️ 火控待复验**：第 11/12 项修改了火控选角逻辑（放宽了正确的命中判定）。
虽然 30 回合验收记录（`scripts/fire_strict_v3.jsonl`）是在修改前取得的，
但改动方向是"更多真实可命中的角度被接受、选角仍按 traveled 最短"，
理论上只会让"无解回合"变少。**仍需重跑一次严格验证**（`scripts/fire_verify_strict.py`，
30 回合，约 1~2 小时）才能重新盖章。现在可以用
`scripts/start_local_game.py` 自动布置"方向键 vs WASD"的 2 人局后再跑，
整套验收可无人值守。
