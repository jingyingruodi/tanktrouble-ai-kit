# 28 · 前端 2026-10-28 版本适配（2026-11-04）

> 背景：站点更新到 `RELEASE-2026-10-28-02` 后，旧缓存 bundle 与新前端资源不匹配，
> 页面上迷宫墙面/部分贴图变成黑块；同时 `GameManager.getGameController` 取不到。
> 本文记录排查、修复与回归。

## 1. 现象

- 页面标题正常、`GameManager` 存在，但游戏贴图（尤其迷宫墙面）显示为黑色方块；
- `GameManager.getGameController()` 返回 `null`/不存在，`start_local_game.py`、
  `test_interface.py`、监控/录制都无法拿到游戏状态；
- 页面网络里 `build/assets/images/atlases/*.avif` 等资源 **404**。

## 2. 根因

两个独立问题叠加：

1. **缓存 bundle 与新前端不匹配**
   - 前端更新后 bundle 变为 `index-7YFIRIU3.js`，资源哈希也变了；
   - 旧缓存 `C:\Users\Administrator\tt_bundle.js` 是 2026-10-26 的版本，
     其中引用的旧贴图哈希在当前服务器已经 404 → 黑块。
   - 修复：用浏览器同源请求/带 UA+Referer 的 curl 重新下载当前 bundle，
     保存为新的 `tt_bundle.js`，重新用 `--bundle` 打补丁。

2. **patcher 的 `GameManager` 签名过宽**
   - 原签名 `c => c && (c.phaserInstance !== undefined || typeof c.getGameController === 'function')`
     是 OR；新 bundle 里存在只有 `phaserInstance` 的普通函数/类，被误匹配成 `window.GameManager`；
   - 结果 `window.GameManager` 是 Function，没有 `getGameController`；
   - 修复：改为 **AND**：
     ```js
     GameManager: c => c && c.phaserInstance !== undefined
                       && typeof c.getGameController === 'function'
     ```

## 4. 运维注意

- **每次站点前端发版后，必须刷新本地 bundle 缓存**；`--bundle` 不能指向旧版本。
- 若 patcher 自动下载 bundle 遇 403，可用浏览器同源 fetch 或：
  ```bash
  curl --compressed -A "<UA>" -e https://tanktrouble.com/game \
    -o C:/Users/Administrator/tt_bundle.js \
    https://tanktrouble.com/build/js/index-<hash>.js
  ```
- 页面初始 Phaser 状态可能是 `Boot/Preload/Main`；patcher 重新加载后应回到
  `Menu/Lobby/Game`，`start_local_game.py` 依赖后者。
- 标准 Edge 在后台/遮挡时仍可能冻结帧循环；长测试保持窗口前台，或使用插件浏览器。
