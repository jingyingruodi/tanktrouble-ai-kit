# TankTrouble AI 游戏接口总览

> 目录：涉及 AI-A（游戏接口）负责的整体架构、CDP 原理、端口分配、已验证功能、快速开始。
> 首页入口见 [README.md](README.md)。

基于 **Chrome DevTools Protocol (CDP)** 直接驱动 Edge 浏览器，对官方 TankTrouble 游戏进行自动化控制与数据采集。无需 Tampermonkey、无需 Selenium/Playwright。

## 快速开始

### 1. 启动 Edge CDP 实例

```powershell
# 启动 2 个实例（端口 9222, 9223，独立 profile 互不干扰）
.\start-farm.bat 2
# 或
python tt.py farm 2
```

**重要**：`--user-data-dir` 路径不能含空格。程序自动用无空格目录。

**两套 profile 方案（互不通用，登录态各自独立）**：

| 启动方式 | profile 目录 |
|---------|-------------|
| `cdp_tools/edge_multi.py`（`python tt.py farm N` / `start-farm.bat`） | `C:\tt-cdp-<i>` → `C:\tt-cdp-0`、`C:\tt-cdp-1` |
| `launch_cdp.py`（各 `.bat` 启动器：`启动-CDP浏览器.bat` / `启动-监控室.bat` / `重启-监控室.bat`） | `C:\tt-cdp\p<port-9222>` → `C:\tt-cdp\p0`、`p1`、`p2` |

> ⚠️ 这是**两套独立的 cookie/登录存储**：在 `C:\tt-cdp-0` 里登录不会同步到 `C:\tt-cdp\p0`，反之亦然。
> 当前只有 `C:\tt-cdp\p*` 这套带着已保存的登录态（`p0` 的 cookies 于 2026-10-02 重写）；`C:\tt-cdp-<i>` 的 cookies 停留在 2026-08-02。
> 需要登录态的多人脚本，请用 `.bat` 启动器（`p*` 方案）；`tt.py farm` 起的实例要重新登录。

### 2. 查看 CDP 窗口 ID

```powershell
python tt.py list
```

输出示例：
```
port 9222: Edg/154.0.4258.37
    [page id=0CBBD82525D0859A...] https://tanktrouble.com/game
```

**`page id` 就是 CDP 窗口的 target ID**——用于通过 `ws://127.0.0.1:<port>/devtools/page/<id>` 精确连接某窗口。

### 3. 检查实例状态

```powershell
python tt.py ping 9222
```

### 4. 运行接口测试

```powershell
# 测试 tank 控制（左转/右转/前进/后退/开火，每步 GET 验证）
python tt.py test 9222 0
```

### 5. 自动开一局本地局 + 绑定控制角色

```powershell
python tt.py local 2          # 2 人本地局；端口可写 auto
# 等价：python scripts/start_local_game.py 2
```

### 6. 跑在 ego 浏览器上（推荐：窗口不会被后台冻结）

项目也支持直接用 DSH 的 ego 浏览器（Edge）作自动化载体，端口不需要预先知道：

```powershell
python cdp_tools/ego_browser.py     # 自检：打印解析到的端口/来源/页面
python tt.py ping auto              # 端口参数写 auto 即可
python scripts/start_local_game.py auto
```

- 端口**由系统随机分配**（`--remote-debugging-port=0`），真实端口写在
  `C:\Users\Administrator\AppData\Local\ego-lite-linux\browser.json`（当前示例：51109）。
- `cdp_tools/ego_browser.py` 的 `resolve_port('auto')` / `discover()` 自动解析，
  ego 浏览器未运行时回退扫描 **9222-9231**。
- **`auto` 只在 `tt.py` 与 `start_local_game.py` 的端口参数上生效**；`scripts/loop_suicide.py` 等只接受数字端口。
- 它的常驻 profile 窗口不像普通 Edge 后台标签页那样被冻结（见 `07` 的"浏览器冻结问题"）。

## SET 控制核心原理

**在线多人是服务器权威**：服务器拥有坦克坐标，每帧把权威状态推回本地。脚本直接改本地坦克对象（`setForward/setRotation/setFireDown`）不会触发 `emitTankState`，服务器不知道你的操作 → 下一帧覆盖回来（回弹），开火被忽略。

**唯一有效链路**（与真实键盘输入完全同路径）：

```
InputState.withState(playerId, fwd, back, left, right, fire)
    → gc.setInputState(inputState)
    → setTankState + emitTankState（发服务器）
```

**已验证坐标映射**：
```
前进方向角 (atan2 dy,dx) = tank_rotation - π/2
rot=0        → 朝上 (-y)
rot=π/2      → 朝右 (+x)
转向速度     ≈ 4.5 rad/s（setInputState left/right 按住）
转向符号（实测验证）：LEFT → drot<0（旋转值减小），RIGHT → drot>0（旋转值增大）
  → 需要旋转值变大（diff>0）时用 turn_right / set_input(right=True)
```

> ⚠️ `setRotation` / `SetPositionAndAngle` 在线**完全无效**（服务器回弹）。`setForward` 系列直接调用仅本地局可用（`_tank_do`/`hijack`，供本地调试）。

## 常见问题

**Q: 为什么在线模式脚本控制会"回弹"（位置被拉回去）、开火无效？**
在线是服务器权威。直接调 `tank.setForward/setFireDown` 只改本地字段、不发 `emitTankState`，服务器覆盖回来。**必须走 `setInputState` 链路**（用 `TankCtl.set_input` 或 `move_forward/turn_left/fire` 等封装方法）。

**Q: 坦克 `isAlive()` 为什么报错？**
坦克对象没有 `isAlive()` 方法。判断存活看坦克 id 是否还在 `getTanks()` 里（`gameutils.tank_alive`）；对象残留但位置连续多次不变视为"冻结尸体"（`loop_suicide`/`suicide_script` 用位置停滞判定，不是速度）。

**Q: 端口冲突？**
默认从 9222 起。`EdgeFarm` 自动递增。检查占用用 `python tt.py list`。

**Q: 换了启动方式后登录态没了？**
两套 profile 方案各存各的 cookie（`C:\tt-cdp-<i>` vs `C:\tt-cdp\p<port-9222>`，见"快速开始"第 1 步）。要么在目标 profile 里重新登录，要么统一用 `.bat` 启动器。
