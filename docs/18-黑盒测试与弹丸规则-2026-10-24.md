## 3. ★ 黑盒测试发现的两个真实包缺陷（本轮已修）

### 3.1 "炮管方向自伤"假象（车体中心 vs 炮口）

`raycast/scan` 原实现从**车体中心**起算。车体矩形（3×4m）把起点包住 →
射线方向 ≈ 当前炮管方向时，官方弹道会在 **1.3m、0 bounce** 处返回 `hit_pid=自己`。

实测对照（炮管方向 ±13°）：

```
origin_offset=0   → 全部 hitTank=自己, b=0, trav=1.3m     ← 假象
origin_offset=2.5 → None(68~93m 通畅) 或 真实反弹(b=1/5)  ← 正确
```

**修复**：`scan/raycast/find_aim/aim_and_fire` 全部按**当前武器炮口偏移**起算
（基础弹 2.5m、加特林 3.0m、霰弹 2.45m、双管 2.25m）→ 直线出膛不再误判自伤。

### 3.2 射程未过滤 → 预测"能中"但子弹差一点点消失

推演给 `max_dist` 留了 1.5× 余量却没按射程过滤，扫出过 **194.6m** 的解，
而基础弹真实射程 = 18 m/s × 10s = **180m** → 子弹在目标前一点点到期消失
（这正是"看起来就差一点点"的直接原因）。

**修复**：`scan/raycast` 结果按 `traveled ≤ max_traveled`（默认 180m）过滤，超出判为不可达。

## 4. ★ 弹丸反弹规则修正：**反弹次数没有上限，唯一上限是存活时间**

**用户实测**：窄通道里弹丸会反弹 **十几次甚至 20 次**。

**源码**（`index-4YALVKHK.js` 弹丸类）：

```js
hitMaze(){ this.bounces.push(Date.now()) }        // 记一次反弹时间戳
update(e){ this.timeAlive += e;
  let t = Date.now() - this.timeoutWindow;        // timeoutWindow=35（本意是秒！）
  for(...) if (this.bounces[i] >= t) { this.bounces.splice(0,i); break; }   // 清掉"过期"反弹
}
done(){ return this.timeAlive >= this.lifetime || this.stopped
              || this.bounces.length >= this.timeoutBounceCount }         // 名义 5 次上限
```

* `timeoutWindow=35` 与**毫秒**时间戳相减 → 有效窗口只有 **35ms** → 反弹计数随清随空；
* **游戏内实测**（`scripts/measure_bullet_bounces.py`）：计数 `0→1→2→3→2→1`，几秒内被清空；
* 因此 `bounces.length >= 5` 几乎永不触发 → **弹丸只在 `timeAlive >= lifetime` 时消亡**；
* 对模型：**不要按反弹次数截断**，只按 `max_dist = 弹速 × 寿命` 限制
  （基础弹 180m、加特林≈54m、霰弹≈64m、激光 180m）。

已修正：`cdp_tools/ballistics.py`（`MAX_BOUNCES` 仅作推演安全上限并注明）、
`cdp_tools/official_ballistics.py`（`bounces_max=None` + 注释）、`docs/14`。

## 4.1 ★ 自伤标签机制（`deadlyToOwner`，上个 agent 的发现，本轮源码+实测复核）

**源码**（弹丸碰撞处理 `PreSolve`）：

```js
MAZE|PROJECTILE   → projectile.makeDeadlyToOwner()          // 第一次撞墙：变"可伤发射者"
TANK|PROJECTILE   → (projectile.isDeadlyToOwner() || tank.playerId !== projectile.playerId)
                      ? TANK_DEADLY_COLLISION               // 已翻转 或 非发射者 → 致命
                      : e.SetEnabled(false)                 // 未翻转且是发射者 → 穿透（无害）
SHIELD|PROJECTILE → 未翻转且是发射者：不碰撞；否则 makeDeadlyToOwner()
HOMING_MISSILE    → 激活后立刻 makeDeadlyToOwner()
MINE              → 部署时立刻 makeDeadlyToOwner()
```

**游戏内实测**（本地局，逐帧采样弹丸对象）：

```
timeAlive=0.02s  deadlyToOwner=False  bounces=0   pos=(17.8,15.5)
timeAlive=1.24s  deadlyToOwner=True   bounces=1   pos=(39.3,19.2)   ← 第一次撞墙瞬间翻转
```

**结论**：弹丸**出膛后到第一次撞墙/撞盾之前，对发射者无害（会穿透自己）**；
翻转后才可能自伤。**对 AI 扫描判定的意义**：`self_hit` 只在**反弹次数 ≥1** 时才算真正的自伤风险
（0 反弹命中自己 = 穿透，无害）。`ttkit` 的 `scan()` 已按此实现，并额外返回
`self_hit_harmless` 字段供调用方区分。

## 7. 第二轮黑盒测试（v2 前）发现的问题与修复（2026-10-24）

第二轮测试（全新受限目录 `tt_blackbox2`，子智能体 60s：**3 发 3 中**、2 次复核不中主动放弃、
0 errors、只控自己 pid）暴露了以下问题（按影响排序）：

### 7.1 影响命中率
1. **转向精度固定 1.7° 且只回 bool**：实测 `ok=True` 时误差 0.4~1.66°；
   而 **0.43° 的角度差就能让官方弹道拓扑突变**（实测 `150.0°/107.4m/8反弹` → 实际 149.6° →
   `187.0m、hit=None`；`210.0°/129.9m/9` → 实际 211.7° → `233.0m、hit=None`）。
2. **转向输入按物理帧量化**：单次脉冲约 4.8° 的整数倍（0.005~0.04s → 9.45~14.32°，0.08s → 24.06°）。
3. **官方 raycast 与真实弹丸在长多反弹路径上累积偏差**：跟踪一发 132m/7 反弹的"预测命中"弹，
   横向偏差 0.44 → 1.31 → 2.27 → **7.45m**（t≈6.5s）→ 脱靶；另一例 173m/13 反弹、
   115m/10 反弹的"实际角度复核命中"弹也全部真实 miss。**短距/少反弹才可靠**。
4. **射程默认写死 180m**：加特林/霰弹寿命 2s（54/64m），不按武器取会误报远距解。
5. **`raycast` 未命中时 `traveled` 返回 270**（=1.5×射程截断值），易被误读。

### 7.2 文档与实现不一致
6. `my_pid()` 找不到角色时**静默回退** `sorted(pid)[0]`（文档说抛异常）→ 有控错风险。
7. `stop()/turn_to_angle()/navigate_to()` **不校验 pid 是否可控**（只有 hold/fire 校验）。
8. `rotation()` 文档说"累积 rot"，实际返回归一化 [-π,π)。
9. `Kit.close()` 只关一条 CDP 连接（connect 建了两条）→ 泄漏。
10. README 写 `scan ≈0.5s`，实测 **0.01~0.02s**；README"<14m 会越过目标"未复现（6.1m/17m 均命中）。

### 7.3 v2 修复（`kit/ttkit/__init__.py`）
* `turn_to_angle()` 改为**高频小脉冲闭环**（委托 `turn_to_rot`），返回 `{ok, actual_deg, err_deg}`，
  实测残差 **±0.4~1.0°**；
* 新增 `aim_and_fire()`：**转向 → 在实际朝向上 `raycast` 复核（含 ±robust_deg 鲁棒检查）→ 通过才开火**，
  失败返回 `reason`（`no_aim/verify_failed`）；
* `scan(..., robust_deg=1.5)`：新增 `robust`（±1.5° 邻域仍命中）与 `quality`（= traveled+30×bounces）；
* 射程按**当前武器**自动取（`WEAPON_RANGE`）；`raycast` 新增 `hit`，未命中 `traveled` 截断到射程；
* `_require()` 统一校验所有控制方法；`my_pid()` 找不到角色**抛 RuntimeError**；
  `rotation()` 返回原始累积值（另给 `rotation_norm()`）；`close()` 关两条连接；
* 新增门面 API：`weapon / bullet_range / range_of / terrain / open_tiles / plan_path /
  maze_distance / projectiles / move_back`；`stop()` 内置等稳；`navigate_to(timeout=)`。

> 修复后冒烟验证：`turn_to_angle` 四个目标角残差 −0.41~−0.98°；
> 坏位置下 `aim_and_fire` 正确返回 `verify_failed` 而**不开火**（安全优先）。

## 8. 第三轮黑盒测试（v3 前）发现的问题与 v3 修复（2026-10-24）

第三轮（`tt_blackbox3`，v2 包，子智能体三跑 **17 发 14 中 ≈82%**）暴露：

### 8.1 三个影响命中/生存的问题
1. **自伤误判 → 被自己的偏弹打死**：`raycast` 报"命中对手、self_hit=False"的 `6 反弹/104m` 解，
   实弹偏了 **16.5m** 打死了发射者自己；另一发 `150°/6反弹/103.9m` 同样打中自己。
   → 官方零宽射线的 `self_hit` **不足以防自伤**。
2. **`aim_and_fire` 的 ±1.5° 鲁棒条件过严**：窄窗口图上所有解 `robust=False` → 3 次 attempt 后
   `verify_failed`，**几乎永远不开火**（子智能体只能手动 stop→turn→raycast→fire）。
3. **`turn_to_angle` 在容差附近极限环振荡**：单脉冲约 5~7.5° > tol 1.2°，来回弹满 150 次迭代
   （≈11s）后 `ok=False`、残差可达 ±7.5°。

### 8.2 其它
* `scan` 30° 太粗（命中窗口 1~3°）→ 需要 10/5/2° 细化；
* `find_aim_angle_raycast` 的预筛用旧回合墙缓存（迷宫每回合重生成），Kit 无复位入口；
* 官方推演 vs 实弹偏差量化：10 反弹/156m → 最近距 25.5m；6 反弹/104m → 16.5m；
  4 反弹/87m → 2.8m；2 反弹/44.9m → 7.6m；
* `scan` 不返回 path（无法预检自伤）；`navigate_to` 吵且无进度信息。

### 8.3 v3 修复（`kit/ttkit/__init__.py`）
* **新增自伤风险 `self_risk`**：官方射线**第一次反弹后**离自己车体中心的最小距离（米）；
  `self_risk < SELF_RISK_RADIUS(4m)` → `self_risk_ok=False`。`raycast/scan` 都带此字段，
  `aim_and_fire` 默认要求 `self_risk_ok`（宁可不开枪也不自杀）。
* `aim_and_fire` 的 `robust_deg` **默认关闭**（改为显式可选）；主要校验：实际角命中目标 + 无自伤风险。
* `turn_to_angle` 自适应：接近目标缩小脉冲、检测过冲回退并接受**最佳可达角**，返回 `best_err_deg`。
* 新增 `scan_adaptive(steps=(30,10,5,2))`（粗→细，一找到安全候选即返回）、
  `is_good_candidate()`、`wait_target_gone()`、`navigate_to_ex()`、`reset_maze_cache()`；
  `scan` 每项新增 `path/self_risk/self_risk_ok`；`roles()` 缓存 1s。

### 8.4 v3 冒烟验证
```
turn_to_angle(2.0) → ok=True actual=112.15° best_err=2.44°
scan_adaptive steps=[30,10,5,2] → 安全候选 2 个（44°/46°，self_risk 6.4~6.6m）
aim_and_fire → fired=True
```

## 9. 第四轮黑盒测试（v4 前）发现的问题与 v4 修复（2026-10-24）

第四轮（`tt_blackbox4`，v3 包，90s）：**5 发 3 中、0 自伤、0 错误、只控自己 pid**；
另一次同逻辑 90s 为 6/6 中。发现：

### 9.1 关键问题
1. **`turn_to_angle` 返回的 `actual_deg` 是"过程最优"不是最终朝向**：自测 8 次最大差
   9.74°/14.30°，`ok=True`、`best_err<3°` 时真实朝向仍可偏 5~14°。
2. **转向分辨率 ±1~5° vs 命中窗口 1~3°**：1° 就差出"2 反弹 53m ↔ 6 反弹 123m"；
   对同一目标角**稳定偏同一量**（量化误差），单纯重试无效，需残差补偿/就近微调。
3. **`scan_adaptive` 粗步长一有候选就返回** → 12 反弹长解掩盖近角短解。
4. **出膛方向 0° 误差仍大偏**（b3/67m 偏 10.46m；b1/15.7m 偏 15.94m）→ 偏差在第一次反弹后：
   官方 `calculateProjectilePath` 用 **零宽射线**（无 0.25m 弹丸半径），掠射反弹点必然偏；
   `calculateFiringPath` 起点是 -Y 偏 2m，而实弹出生 2.5m。
5. **`self_risk` 对长弹道不够保守**：b8/119.6m/risk=18.8 实弹偏 11.77m 后**打死自己**。
6. 其它：`quality` 不含 `self_risk`；`navigate_to` 慢且吵；`wait_target_gone` 混淆击杀与回合切换；
   README 与 `tank_constants` 的"反弹次数上限"表述矛盾（实测 9 次反弹仍活）；
   霰弹 weapon=2 的 `raycast` 仍是单发直线模型（未建模散射）。

### 9.2 v4 修复（`kit/ttkit/__init__.py`）
* `turn_to_angle`：循环结束后 **`wait_still` + 重读 rotation**，`actual_deg/err_deg` 返回
  **停稳后的最终朝向**，新增 `final_err_deg`（`best_err_deg` 保留过程最优）；
* `scan_adaptive`：默认**合并所有步长**的候选（按角度去重、quality 排序），
  `stop_early=True` 可恢复旧行为；
* `is_good_candidate`：新增策略参数（默认 `bounces<=6`；
  长弹道 `bounces>=5 或 traveled>=100` 要求 `self_risk>=20m`）；
* `quality` 纳入 `self_risk`：`traveled + 30*bounces + 5*max(0, 20-self_risk)`；
* 新增 **`fine_aim()`**：在给定角 ±span 内 1° 细搜"命中且安全"的最近角；
  `aim_and_fire` 复核失败时自动调用它微调后再复核（v4 新增 `fine` 字段）；
* README v4：补充"零宽射线 vs 0.25m 弹丸""firing path 2m vs 实弹 2.5m""霰弹散射未建模"。

## 10. 第五轮黑盒测试（v5 前）发现的问题与 v5 修复（2026-10-24）

第五轮（`tt_blackbox5`，v4 包，90s）：**4 杀 / 80% 命中 / 0 自伤 / 0 错误 / 只控自己 pid（三重证明）**。
它做了**按弹丸 id 锁定的单发轨迹对比**，得出关键结论：
* 预测路径**首反弹误差仅 0.3~0.6m**，4 连反弹样本也吻合（预测 `(12.29,39.6)→(0.4,19.39)→(11.58,0.4)→(16.99,9.6)`
  vs 实测 `(12.4,39.2)→(0.8,19.5)→(12.0,1.2)→(16.4,8.7)`）；
* **本机打偏的主因是"瞄准量化 ±1° × 命中窗口 1~3°"**，不是推演公式；
* 它自写 `turn_precise`（连续按住+高频读+提前释放+过冲补偿）把残差从 3.6~6° 压到 **mean 0.8~1.2°、max<4°**。

### 10.1 发现的问题
1. **`turn_to_angle` 精度差**（实测 mean 3.64~5.97°、max 12.66°）：最小脉冲 0.008s 在 30Hz + CDP
   往返下退化成 1~5 个物理帧（~4.8°/帧）；`flips>=3` 提前 break；返回的 `actual_deg` **未归一化**（实测 394.8°）。
2. **`weapon(pid)` 可能返回 None**（回合间隙）→ 内部 `int(None)` 抛 TypeError，火控链全挂。
3. **隐藏弹药**：默认武器 **5 发/回合**（`getRoundState().data.weaponStates[].fieldsJSON` 的
   `_bulletCount/_bulletsFired`）；第 6 次起 `fire()` **静默无效**。
4. **无命中归因**：`destroyedPlayerIds` 回合重置后常清空；`wait_target_gone` 混淆击杀与回合切换；
   多弹在飞无法归因到某一发。
5. **`is_good_candidate` 默认策略在窄地图全灭**（命中解普遍 4~13 反弹）：360° 全扫 0 候选是常态，
   需放宽档（b≤8、trav≤140、risk≥6）才有出手机会。
6. **`fine_aim` 写死策略且返回"最近角"** → 瞄到窗口边缘（窗口 1~3°、误差 1~2°）。
7. 死亡判定滞后 0.2~0.4s；`position()` 短暂 None 被误判为死亡；`navigate_to` 阻塞无中断。

### 10.2 v5 修复（`kit/ttkit/__init__.py`）
* **新增 `turn_precise()`**：长按住 + 每 8ms 读 raw rot + **到达阈值即取消任务松键**
  （用 `set_input` 的 finally）+ **递减提前量补偿**（1.2°→0.72°→0.43°→0.26°）。
  实测残差：4/5 在 ±1.4° 内、mean 2.36°（含 1 次回退）；
* `turn_to_angle()` 优先用 `turn_precise`，失败退回脉冲自适应；`actual_deg` **归一化到 [-180,180)**；
* `weapon=None` 防线：统一 `_muzzle()`（None/未知 → 2.5m），`range_of` 同样容错；
* **新增 `ammo(pid)`**（`{left,fired,weapon}`）、`bullets_in_flight(pid)`（归因用）；
* **新增 `destroyed_pids()` / 强化 `alive()`**（先查 destroyed、再查 position、短暂 None 重试）、
  `position_confirm()`；
* **`scan_adaptive` 多档**：`profiles=('strict','relaxed','loose')`，先 strict 全扫，全灭再放宽；
  候选带 `tier` 字段；`Kit.PROFILES` 可查参数；
* **`fine_aim` 改为"命中窗口中心"**：0.25° 采样建窗，返回离中心最近的窗口中心角（带 `window` 宽度）；
* 新增 `navigate_segment()`（有界单段，段间可扫描）。

## 11. 第六轮黑盒测试（v6 前）发现的问题与 v6 修复（2026-10-24）

第六轮（`tt_blackbox6`，v5 包，两次 90s）：**各 4 杀 / 0 错误**；游戏 `gc.getScores()`
击杀数 **9→13→17** 与命中数完全一致（无可争议的归因）；只控自己 pid（三层护栏，
底层 `set_input`：own 711 次、other 0 次）。

### 11.1 发现的问题（v5 缺陷）
1. **`ammo()['left']` 是弹匣容量**（`_bulletCount` 恒 5、开火不递减）→ README 的
   `left<=0` 检查永不成立；真正剩余 = `left - fired`（第 6 发 `fired` 不增 = 静默无效，已实测复现）。
2. **`scan()` 固定角度网格不含"正对目标"的直线角**；命中窗口 1~3° 时可能整窗漏掉。
3. **`fine_aim` 默认 `profile='strict'`** → 对 relaxed(6~8 反弹) 解返回 None；
   且会返回**另一条更长的解**（日志 `[fine 换了路径 2b/53m→3b/62m]`）。
4. **无比分/回合 id API**：本地局一击必杀后回合立即重置，`alive()/destroyed_pids()/
   wait_target_gone()` 来不及观察；命中只能靠 `gc.getScores()` 增量归因。
5. `rotation()` 瞬时 None（死亡/换回合帧）会 `TypeError`；`navigate_segment` 首段可能位移 0m；
   `turn_precise` 有离群值（实测 −6.29°~+3.03°），一次离群就让弹道出窗。

### 11.2 v6 修复（`kit/ttkit/__init__.py`）
* `ammo()` 增加 **`remaining = left - fired`**（保留 `left/fired/weapon`），文档明确 left 是容量；
* 新增 **`scores()` / `kills_of(pid)` / `round_id()`**：解析
  `{scoreId:{playerId,type,value}}`（type 0=击杀/1=胜局），用于开火后比分归因；
* `scan(..., include_targets=True)`：额外采样"正对每个对手"的 ±1.5° 直线角；
* `fine_aim(profile=None)`：自动 strict→relaxed→loose；新增 `ref_bounces/ref_traveled/same_family`
  ——拒绝换成反弹数 +2 或行程 +25%+10m 的"另一条解"；
* `rotation()` 瞬时 None 重试一次；`navigate_to_ex()` 返回 `from/moved`；
  `turn_precise()` max_rounds 4→6、返回 `outlier`（|残差|>3°）；头注释/README 升到 v6。
