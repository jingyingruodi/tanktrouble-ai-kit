## 1. 三篇文档的一句话结论

| 文档 | 一句话 |
|---|---|
| 微操神大局废（综述） | 「微操神、大局废」不是训练不足，是**四层机制叠加**：奖励密度失衡 / 无地图拓扑表示 / 动作只有原语 / 自对弈选择压力坍缩；文献里有四条已验证修法（**A\* 规划器子目标 90.2%→98.9%**、macro-micro 分层、推进型指标、基于模型的动作剪枝）。 |
| 游戏AI追求智商用什么 | 游戏 AI 的"智商" ≈ **经验质量 × 奖励设计 × 观测设计**；模型大小几乎不在公式里（OpenAI Five 仅 1.59 亿参数、单层 4096 LSTM，靠自我对弈 + 手工观测/奖励）。 |
| TankTrouble-AI设计文档 | 现有 RL 尝试的 5 个结构缺陷（无拓扑、无记忆、全微操奖励、全原语动作、单步 TD）→ 提**三层混合智能：L0 解析层 + L1 战术层 + L2 战略层**；核心口号「**能算的别学，学不会的才学**」。 |

**三篇的共识**：宏观能力是**结构问题**，不是容量问题；且都指向同一个抓手——**把可精确计算的几何/拓扑从神经网络里剥出来，做成解析层与规划器**。这正好是本项目已经验证过的区域（见 §2）。

### 2.3 三篇文档的"5 个结构缺陷"对照我们的现状

| 缺陷（doc3 §2.3） | 现有 RL 尝试 | 我们的 `rl/obs.py` v1 | 结论 |
|---|---|---|---|
| 状态无拓扑（8×8 二值墙） | 有 | **同样有**（局部 3 通道网格，仍是位图不是图） | **需补**：拓扑/可达/危险场 |
| 策略无记忆（纯 MLP） | 有 | env 单步 obs（无历史栈） | **需补**：GRU/小 Transformer |
| 奖励全微操 | 有 | kill/death/survive/pickup/time（有交易信号，无位置价值） | **需补**：宏观项 |
| 动作全原语 | 有 | Discrete 6/7 | **需补**：动作屏蔽 + 可选宏动作 |
| 单步 TD | 有 | PPO 可缓解（但仍是短视） | 用 PPO+GAE+宏观奖励 |

## 3. 三篇文档与实测的**修正项**（重要，避免被二手描述误导）

1. **反弹次数**：不是"可能很多次"——游戏有硬上限 **5 次**（`PROJECTILE_BOUNCE_TIMEOUT_COUNT=5`，运行时弹丸字段 `timeoutBounceCount=5` 已确认）。危险场/威胁图的时间与反射层数只需算到 5 层。
2. **弹丸寿命因武器而异**：基础弹/双管/追踪弹 10s，**加特林/霰弹只有 2s**（射程≈54/64m）。威胁图必须按武器分桶，否则会高估加特林/霰弹的覆盖范围。
3. **炮口偏移因武器而异**：2.25~3.0m（双管 2.25、加特林 3.0、基础 2.5）。反弹路径对起点极敏感——这也是我们当前火控打空的可疑根因之一。
4. **自伤有精确规则**：`deadlyToOwner` 在**第一次反弹后**才翻转为 true → **直线自射无害**，动作屏蔽不能一概屏蔽"朝自己方向开火"。
5. **计分的正确定义**：自杀**不给任何人加分**，但会让对手拿到 VICTORY（=输掉该回合）。奖励设计应把"自杀"视为**输回合**，而不是看 KILL 分。
6. **参考 C++ 代码不在本工作区**：doc3 引用的 `Rachel1477/DRL_for_TankTrouble` 未包含在本地；本地的 `tanktrouble_ai2` 是同类尝试（同样的 8×8 网格问题），可作为训练骨架复用。

## 4. 落地路线（按我们的现状与优先级）

> 前置：**火控"瞄准角↔坦克 rot"映射未解决前**，实时对局数据质量受限（docs/14 §2.4）。
> 该问题不影响仿真器训练，但影响"真机验证/评测"的可信度 → 建议并行推进。

### P0（立刻，1-2 天）：补齐真机链路的可信度
* 标定 `setRotation(x) → getRotation()` 映射，修 `turn_to_rot`（docs/14 §2.4）；
* 复用 `compare_predicted_path.py` 做闭环标定（设定 rot → 开火 → 实测首段方向）；
* 重跑 `fire_verify.py` / `fire_verify_strict.py` 各两遍做回归验收。

### P1（1 周）：**校准仿真器 = 训练地基**
* 用我们的实测参数校准 `tanktrouble_ai2/game_engine.py`：
  完美镜面反射 ✓、弹速（18/25-30/30-35/180）、寿命（按武器）、**反弹上限 5**、**弹丸半径/炮口偏移**、坦克尺寸；
* 加**回归测试**：从 `game_source/constants.js` 自动读常量比对；用我们录制的真实弹道做"仿真器 vs 真机"偏差测试（目标 < 0.3m）；
* 产出：`tanktrouble_ai2` 的引擎能作为"真机的数字孪生"（参数同源、误差可量化）。

### P2（1-2 周）：**L0 解析层**（doc3 的核心创新，收益最大）
在仿真器/真机共用实现：
* **弹道引擎**：`trace(origin, angle, map, weapon)` → 折线 + 逐时刻位置（已有 `official_ballistics`，抽成纯函数）；
* **威胁/危险场**：对每个格子算"敌方从当前位置能打到的角度集合"（反射可见性多边形，层数 ≤5）；
* **可达图**：Dijkstra（坦克速度已知、格=10m）；
* **位置优势 Advantage**：`Safety / Escape / Control / Choke(割点, Tarjan) / Loop(双连通分量) / Pickup / Rel` 加权标量化；
* 产出：`lowlevel/` 或 `tanktrouble_ai2/analytic/` 模块 + 单元测试（用我们的迷宫 API 对拍）。

### P3（1-2 周）：**obs v2 + reward v2 + 动作屏蔽**
* `rl/obs.py` 升 `OBS_VERSION=2`：新增
  * **危险场局部裁剪**（9×9）；
  * **最佳开火角三元组**（能否命中/角度/飞行时间，来自 P2）；
  * **waypoint 相对位置**（来自 P4 规划器）；
  * **拓扑摘要**（割点距离、环路入口、拾取距离）；
* `rl/env.py` RewardConfig 升 v2：加
  * `w_adv·ΔAdvantage`（**每帧持续型**，不是稀疏事件）；
  * 咽喉控制时长、劣势区惩罚、探索新区域（scout 指标）；
  * 权重原则：**“走到好位置”的累计奖励 ≥ “打中一枪”**；
  * 每条奖励上线前做**行为审计**（防 reward hacking）；
* **动作屏蔽**：只屏蔽"必死"（如自杀性直射？注意 §3.4：直线自射无害，只有反弹回来自伤才致命）。

### P4（2-3 周）：**L2 规划器 + 分层训练**
* 在 (x,y,t) 时空图上做 Dijkstra/A*（动态 hazard），输出 3–8s waypoint；
* L2 频率 **2–5 Hz**（doc1 STRATA 的延迟警告）；
* L1 = PPO + GRU（历史 32 帧）+ 解析特征增强；
* 课程 S0→S7（doc3 §5），每阶段验收达标才进阶。

### P5（长期）：**联赛 + 宏观指标评估**
* 联赛角色：Main / Main Exploiter / League Exploiter / **脚本剥削者（龟缩控图流、绕后流、道具流）**——doc3 §6 强调必须有"不跟你打只占位置"的对手；
* 评估用**双轴**：微操（命中率/自杀率/存活）+ **宏观**（平均位置优势、优势区停留率、咽喉控制时间、绕后成功率）；
* `IQ_score = 0.4·胜率 + 0.3·宏观分 + 0.2·微操分 + 0.1·跨地图稳定性`（doc3 §7.3）。

### P6（可选，研究向）：**对外基准对比**
* 用 Pommerman（最像）、ProcGen（泛化）、HLSMAC（战略）做横向对照；
* doc1 §10 指出「反弹弹道 + 连续控制 + 程序生成迷宫」**没有现成基准**——这是我们项目的潜在研究价值点。

## 5. 风险与纪律

| 风险 | 对策 |
|---|---|
| 手工奖励被 hack | 每条奖励先做行为审计；优先"推进型/持续型"指标；用宏观指标做早停 |
| 仿真器与真机不一致 | 参数同源（`game_source/constants.js`）+ 真机弹道回归测试（<0.3m） |
| 只训微操 | 训练/评估都用宏观指标；联赛加入"龟缩控图"脚本对手 |
| 实时真机太慢 | 训练用仿真器（≥1000 步/s），真机只做验证/评测（我们的 CDP 链路 ~30 步/s） |
| 文档中的 2026 年 arXiv ID 未核实 | 对外引用前逐条检索核实；内部以 `game_source` 与实测为准 |

## 6. 结论

三篇文档把方向说对了：**把可算的几何/拓扑剥离成解析层，再让学习层只学"不能算的"**。
而本项目最大的差异化资产恰恰是：**我们已经在真机上把弹道、弹丸参数、迷宫拓扑、计分规则全部验证过了**（偏差 0.2m、逐格 100%）。
所以正确姿势不是"从零训一个大网络"，而是：

> **用我们验证过的规则去校准一个快速仿真器 → 在仿真器上做 L0/L2/PPO 训练 → 用真机（CDP 链路）做验证与评测。**

这条路线同时满足三篇文档的核心建议（规划器、解析特征、推进型奖励、动作剪枝、联赛），
且把我们已有的验证成果变成"训练地基"，而不是重新发明。
