# 32 · 每次前端版本更新的审查流程

> 规则：**只要游戏前端 `RELEASE-*` 或 bundle hash 变化，就必须走完本清单，
> 并由一个上下文干净的子智能体独立复核；未复核不得视为“已适配”。**

## 1. 触发条件

任一出现即触发：

- 游戏页出现新的 `RELEASE-YYYY-MM-DD-NN`；
- `/build/js/index-*.js` 的 hash 变化；
- 官方新闻提到新武器/新机制；
- 线上资源 hash 变化导致 404/黑块。

## 2. 必跑步骤

### A. 记录版本与 bundle

```powershell
# 用浏览器同源/带 UA+Referer 请求，避免 Python 默认 UA 403
curl.exe -sS --compressed -A "<Edge UA>" -e https://tanktrouble.com/game `
  https://tanktrouble.com/game | Select-String 'index-[A-Za-z0-9]+\.js'
```

记录：`RELEASE-*`、bundle 文件名、文件大小、抓取日期。

### B. 重新下载 bundle 并打补丁

- 不能继续用旧的 `tt_bundle.js`（旧 bundle 引用旧贴图 hash，会 404/黑块）；
- 用当前 bundle 重新运行 `scripts/patch_frontend_api.py --bundle ...`；
- 必须检查 `--verify` 的：
  - `GameManager` 是 function；
  - `GameManager.getGameController` 存在（`controllerOk=true`）；
  - `phaserInstance=true`；
- 如果 `GameManager` 又被误匹配，检查 `SIGNATURES` 是否仍要求
  `phaserInstance !== undefined && typeof getGameController === 'function'`（AND，不是 OR）。

### C. 游戏页/资源检查

- 游戏标签页必须前台：`document.hidden === false`；后台会冻结 Phaser，
  导致 `Lobby -> Game` 一直 pending；
- 截图确认贴图完整，不应有黑块；
- 若仍有 404，先检查缓存 bundle 是否还是旧版，而不是先怀疑网络。

### D. 接口回归

```powershell
python scripts/start_local_game.py auto --players 2 --theme 0 --restart
python scripts/test_interface.py 9222
python scripts/selftest_monitor.py
```

门槛：

- local game 进入对局；
- `test_interface.py` **5/5 PASS**；
- `selftest_monitor.py` **PASS**（监控/录制/回放）；
- **新增接口必须专项验收**：`frag_bomb_detonations()` 至少返回一条事件且事件带
  `roundId`；`projectiles()` 含 `typeName/triggered/detonated/detonationTime`；
  monitor WS 的 `fragBombDetonations` 字段可读。只跑旧 5/5 + selftest 不算通过。

### E. 新武器/新常量核对

- 从 bundle 读取 `WEAPON_TYPES / COLLECTIBLE_TYPES / PROJECTILE_TYPES / *_LIFETIME`
  等常量，不能凭新闻描述猜；
- 检查 kit：
  - `WEAPON_NAMES / PROJECTILE_NAMES / MUZZLE_OFFSET / WEAPON_RANGE / WEAPON_SPEED`；
  - `cdp_tools/official_ballistics.py` 的 `WEAPONS`；
  - `monitor_server.py` 的 `MAXLIFE/typeName`；
  - `ammo()/projectiles()/frag_bomb_detonations()` 等观测口径；
- **常量值一致性**：live `Constants` 的属性名没有 `C_` 前缀（例如
  `Constants.FRAG_BOMB_MAX_LIFETIME`）；检查文档/代码/实测数字三者一致；
- 新机制必须实测（至少本地人工发放 + 单测），并注明哪些不能外推。

### F. 训练侧回归

在私有训练项目：

```powershell
python -m unittest research.test_l0 research.test_frag_hazard research.test_reward -v
python research/run_l0_live.py --port 9222
```

- L0/L2 输出正常；
- 新武器 hazard/奖励口径有明确边界；无官方依据的假设必须默认关闭或显式标注；
- 区分敌方母弹（威胁）和己方母弹（自伤风险）；
- 旧对局数据必须标记为旧版本，不能直接沿用。

### G. 多局/刷新/状态生命周期

- 至少切一次回合（或重开本地局），确认 `frag_bomb_detonations` 的旧事件被清空、
  新事件 `roundId` 更新；
- 页面刷新/`--restart` 后重新确认 `GameManager` 和 patcher 仍生效；
- monitor 的 `fragBombDetonations` 不得把回合结束时的 projectile 清空误报为爆炸；
- 记录测试的 `roundId` 与实际事件，不只截图。

### H. 独立审查（强制）

- 启动**上下文干净**的子智能体/队友；
- 给它：仓库路径、两个 commit hash、要跑的命令、当前 `RELEASE-*`/bundle；
- 要求它：
  1. 只看文件和实际测试，不采信聊天结论；
  2. 独立运行测试/监控自检、`git status`、`git show`；
  3. 检查提交 `[dsh]` 标识、公开 diff 无 token/私有训练内容；
  4. 报告 `PASS / CONDITIONAL / FAIL`，列具体文件行和命令结果；
- 审查通过后才能推送/对外说“适配完成”；
- 审查不通过：修复 P1 后重新审查；
- 审查报告落盘到 `docs/33-<日期>-<主题>审查.md` 并在 `docs/README` 加索引。

## 3. 常见坑

| 坑 | 表现 | 处理 |
|---|---|---|
| 旧 bundle >= 新前端 | 贴图 404/黑块 | 重新下载 bundle，不能用缓存 |
| patcher 签名 OR 过宽 | `GameManager` 是 Function，无 `getGameController` | 签名改 AND |
| 游戏页在后台 | Phaser 冻结，状态不推进 | 切前台/`Page.bringToFront` |
| 新武器类型漏映射 | `range_of/ammo/scan` 异常或默认值 | 补 weapon/projectile 常量 |
| 人工发放武器 | 绕过自然拾取/队列 | 结论标注“本地/非自然”，不能当 DPS |
| 爆炸/破片误当普通子弹 | 威胁模型严重低估 | 单独 hazard 模型，标注近似边界 |
