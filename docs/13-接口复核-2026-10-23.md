## 3. 本次发现的真实变更与处理

### 3.1 `UIConstants` 未被补丁导出（已修）

`official_ballistics.py` / `official_aim.py` / `aimer_predict.py` / `aimer_compare.py` 读
`window.UIConstants.AIMER_OFFSET`（=50px=2.5m，炮口偏移）。10/23 复核时该全局不存在 →
`Cannot read properties of undefined (reading 'AIMER_OFFSET')`。

**修复**：`patch_frontend_api.py` 的 `CSIG` 增加
`UIConstants: c => c && c.AIMER_OFFSET !== undefined && c.AIMER_WIDTH !== undefined`。
修复后 `UIConstants.AIMER_OFFSET=50`、`AIMER_WIDTH=4` 正常，弹道模块恢复。

### 3.2 武器弹药字段改名 `_numBullets` → `_bulletCount`（已修）

新发布下武器对象字段：

```
基础弹: {_bulletCount: 5, _triggerPulled, _bulletsFired, _timeAlive}
加特林: {_bulletCount: 20, _triggerPulled, _weaponCharge, _timeSinceFire, _newBurst}
```

`measure_charge.py` 原先读 `_numBullets` → 恒为 None。**已改为优先 `_bulletCount`、回退 `_numBullets`**。
复测：加特林 `numBullets=20` 正常、蓄力 485ms。

### 3.3 `official_ballistics` 与行为层命中判定存在差异（记录，不改）

* 行为层（`find_aim_angle_raycast`）走**游戏官方** `B2DUtils.calculateProjectilePath`；
* `official_ballistics` 是**自建** p2 raycast + 半径感知命中层（坦克半径 2.2、弹丸 0.3、出膛豁免 3.5m）。
  两者对"是否可命中"的判定不同：某次几何下行为层找到 34° 解、自建层判无解；
  换一处几何后自建层正常找到 172.6° 并命中。

**结论**：自建层可用于离线弹道推演/验证（10/16 在线偏 0.26~0.43m），但**火控决策以行为层为准**。

### 3.4 在线弹道复核（已补采：21 发）

**采样方法（实测有效）**：`scripts/fire_record.py <数字端口> --out X.jsonl --fps 60 --dur 45`
（上个 agent 的"录制+开火同进程"工具，比跨进程 `record_only + fire_burst` 稳得多），
**打完立刻在同房间内跑 `validate_ballistics.py`**（页面内预测需要活的 game controller），然后强制退房。

**结果（45s 一组，21 发参与验证）**：

```
观测点 → 预测折线 距离：中位 0.589m  平均 6.110m  p90 18.629m
预测折线 → 观测点 距离：中位 1.359m  平均 13.676m
路径长度绝对误差：中位 2.11m（≈1.2%）
反弹次数（启发式）：真实 ~15~30 vs 预测 ~5~13（中位误差 16）
```

**解读**：
* **中位 0.589m** 与 2026-10-16 的 0.433m 同量级 → 弹道模型仍然可用；
* 但**长尾明显**（均值 6.1m、p90 18.6m）：少数**长路径 / 贴墙擦边**的弹丸会分歧，
  疑似服务端权威物理（在线弹丸由服务器模拟、客户端只镜像）与我们客户端的零宽射线模型
  在"擦边反射"上不同；离线/本地局不会出现这个误差源；
* "真实反弹次数"是**逐帧方向变化 >25° 的启发式计数**（30fps 采样下噪声会虚增），
  与"预测反弹数"不是同一把尺子——判据仍应以**轨迹偏差**为准。

**另一个重要发现（服务端行为）**：**"全部自己人"的自建房在当前服务端下回合不重启**
（实测 120s 内 `roundActive=True` 恒真、坦克死后不重生、录制 29s 就无对局数据）。
→ 在线采样请用 **`--players 1`（服务端配人机）** 的房间，人机会让回合持续重启。

**遗留**：`start_online_game.py` 偶发 `KeyError: '22838087'`（解析房间信息时该 pid 尚未在坦克表里），
属健壮性小问题，重跑即可；后续可加"等坦克表就绪"再解析。

## 4. 运维约束（复核后仍然成立）

1. **`patch_frontend_api.py auto --keep-open` 必须常驻**（每次页面加载都要回填补丁包）；
2. 老脚本（`fire_verify_strict.py` / `record_only.py` / `playback_server.py`）端口参数要传**数字**，
   新脚本可用 `auto`；
3. 本地验收脚本需要**先在 Menu 创角色**（否则本地局配机器人）；
4. 在线驻留必须保活、结束强制退房（`leaveGame(true)`）。
