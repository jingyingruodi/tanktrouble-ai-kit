# 27 · 监控网页 / GET 接口黑盒测试（2026-10-26）

> **测试角度 2（区别于 docs/26 的"AI 自己写火控"）**：让子智能体只读原语、写一个**单页监控网页**，
> 然后在**同一时刻**把"游戏真实渲染"与"监控页渲染"做像素级核对。
> **核心问题：模型从 get/状态接口拿到的数据，和游戏真实状态是否一致？**
> 结论：**坐标/朝向/道具/弹丸/墙线的几何数据可信（0.004 m 级）**；但速度、回合阶段字段、
> 相机/仿真时间/事件流存在明确缺口（v6 已修/已标注）。

## 1. 方法

- 黑盒包：`ttprim` v5 + `VisualPrim`（截图/多页面/页面 eval）。
- 子智能体交付：`tt_monitor_box`（仓库外证据目录）：
  - `monitor.html`：单页监控（无 CDN），10Hz 轮询 `/state`，canvas 画墙体/坦克/弹丸/道具/地雷/毒圈/10m 网格/HUD；
  - `monitor_bridge.py`：stdlib HTTP 桥（`/state`、`/state?raw=1`、`/freeze` 冻结快照等）；
  - `capture_compare.py` + `pixel_audit.js`：同一时刻双截图 + 浏览器内像素核对；
  - `report.md`：完整逐字段报告。
- 场景：dark 主题 “Boot Camp” 6×4 地图，2 坦克、2 道具；游戏前台静止窗口内截游戏页（S0==S1 跨 283ms），
  打开监控页后把桥 `/freeze` 到 S1 再截监控页（269ms）→ 保证两边同一快照。
- **重要方法纠正**：任务书建议的"打开监控页让游戏页后台化来冻结状态"**实测不可靠**：
  后台化只暂停 rAF、不冻结仿真（实测后台期间 rot 4.77→5.91 rad）；后台标签页截图还出现过
  右/下大片白板（`game_bg_partial.png`）。最终采用"前台静止窗口 + 冻结快照"方案。

## 5. 仍然存在的缺口（诚实清单）

1. **相机变换仍不暴露**：只能由调用方从墙线 bbox 反推；scale 随主题/地图变（7.099 / 7.889 / 8.4 px/m 均实测），不能写死。
2. **无原子事件流/死亡坦克信息**：击杀/死亡/回合结束/winner 只能轮询比分与 tank 消失推断。
3. **无仿真时间/帧号**：`game_time_ms` 是 Phaser 时钟；截图与 state 的精确帧对齐仍有 ~325ms 窗口不确定度（18m/s ≈ 5.8m）。
4. **`winner` 恒 null**；`mines/zones/storm` 本次 0 样本，未验证；`collectible.type` 无语义。
5. **dark 主题墙体完整度未定论**：47% 的 state 墙面积不在白墙掩码内，全部位于外围黑边/左下凹口；需 light 主题完整帧或黑边框检测才能判定是"state 多给外框"还是"主题画成黑色"。
6. **监控页轮询实测 3.5–5.5Hz**（代码 10Hz），浏览器可见性节流所致，非接口问题。
7. **后台标签页不可作为冻结/截图手段**（已实测反例）。

## 6. 对训练接口的结论

- **可用于训练的 get 数据（已实测准确）**：坦克位姿（0.004m/0.8°）、墙体中线、道具位置、弹丸
  位置/类型/所属、回合/比分数值、`phase/roundId`。这些足以支撑观测构建与奖励计算。
- **必须按 v6 文档使用的**：速度用 `*_fd`（不要用 `vx/vy`）；回合阶段用 `phase`（不要用 `active/countdown`
  旧语义）；换场稳定用 `round_seen_age_ms`；游戏暂停用 `paused/game_time_ms`。
- **训练前建议补的（按影响）**：① 相机变换/视口；② 原子事件流 + 死亡坦克；③ 仿真时间/帧号；
  ④ `winner` 与 `mines/zones` 语义；⑤ 主题/贴图元数据。
