## 2. 火控验证复跑（上个 agent 的脚本）

| 脚本 | 第 1 遍 | 第 2 遍 |
|------|---------|---------|
| `fire_verify.py`（限时 100s，按击杀分判定） | ⚠️ 100s 内未击杀（机动后超时，无结论） | ✅ **打出击杀 → "火控有效"**（attacker 击杀 0→1、target 0，未误伤己方） |
| `fire_verify_strict.py`（每回合 180s 内必须击杀） | ✗ 回合超时 180s 未击杀 → "火控缺陷" | ⚠️ **1/2 回合有击杀**，第 2 回合超时（加保护后可正常终止并给结论） |

### 2.1 已修复：`fire_verify_strict.py` 会无限等待

实测该脚本在"单回合长时间不出结果"时**一直等下去**（20 分钟迷宫版本不变），
而客户端并**没有卡死**（Phaser `time.now` 正常推进）。**修复**：新增两个参数

```
--deadline N       整轮验证总时长预算（默认 900s）
--round-timeout N  单回合超过 N 秒无"回合状态变化"→ 主动 suicide_by_bounce 结束该回合（默认 240s）
```

修复后复跑可正常终止并输出"1/2 回合成功 / 第 2 回合超时"。

### 2.2 关键诊断：弹道模型没问题，问题在"炮口偏移"

* `scripts/compare_predicted_path.py`：固定炮管角开一枪 → 60Hz 密集采样 → 用实测首段方向预测同起点路径：

```
实测点 → 预测折线：中位 0.21m  平均 0.24m  最大 0.44m     ← 弹道模型准确
```

* 但严格验证里 **26~35m 的反弹弹反复打空**，且目标坦克**静止**（实测 8 秒位移 0.00m）。
* 推断：预测从**车体中心**出发，而真实弹丸从**炮口前 2.5m** 出膛（`Constants.BULLET.OFFSET=2.5`）。
  直线弹道不受起点平移影响，但**反弹路径的反射点会整体平移** → 远距离反弹弹容易偏出。
  这正是上个 agent v8/v9 试 `--muzzle 2.0/2.5` 时"卡在 38°/2 反弹/43m"的现象。

### 2.3 A/B 实验：炮口偏移**不是**主因（已排除）

`scripts/muzzle_offset_ab.py`：每发重开一局、目标静止，两种起点各打 3~5 发：

```
cfg=0.0m（车体中心）    → HIT 0 / MISS 3
cfg=2.5m（真实炮口）    → HIT 0 / MISS 2
```

→ 两种都打空，**炮口偏移不是主因**。

### 2.4 ★ 定位：断链点在"瞄准角 → 坦克转向"

`scripts/aim_fire_direct.py` 把"算出角度 → 转向 → 开火"拆开测：

```
算出的方向角 ang=5.341 → 目标 rot=ang+π/2=6.912
直接 setRotation(6.912) 后实测 getRotation()=0.999    ← 差了 ~0.37 rad（≈21°）
→ 开火 MISS（k=0→0）
```

* 弹道模型准确（§2.2：预测 vs 实测 0.2m）；
* 但**坦克实际朝向与目标朝向差约 21°** → 弹丸沿错误方向飞出 → 必然打空；
* `turn_to_rot`（渐进转向）组几乎全部 `SKIP(no angle)`，`fire_verify.py` 偶尔能命中
  —— 都是"转向/角度映射不稳定"的同一症状。

**结论：火控打空 ≠ 弹道模型问题，而是【瞄准角 ↔ 游戏 rot 的映射/转向精度】环节有问题。**

**下一步（优先级最高）**：
1. 确认游戏 `getRotation()` 的约定（累积角 vs 归一化角）与 `setRotation` 的归一化行为；
   实测 `setRotation(x)` 后 `getRotation()` 的响应曲线，推导正确映射（可能是 `rot = ang − π/2` 或需要考虑累积量）；
2. 用"设定 rot → 开火 → 实测弹道首段方向"做闭环标定（`compare_predicted_path.py` 已有采样能力，可复用）；
3. 标定后重跑 `fire_verify.py` / `fire_verify_strict.py` 各两遍做验收。
