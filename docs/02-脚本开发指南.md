## 2. 快速开始（10 分钟写出第一个脚本）

### 2.1 复制模板

```powershell
cd "<repo>\scripts"
copy tank_behavior_template.py my_behavior.py
```

### 2.2 改 main() 里的逻辑

```python
async def main():
    port = int(sys.argv[1]) if len(sys.argv) > 1 and sys.argv[1].isdigit() else 9222
    bhv = TankBehavior(port=port)
    await bhv.connect()

    roles = await bhv.get_roles()          # 拿到所有可控角色
    pid = await bhv.pick_role('keyboard')  # 选一个

    # 等待回合开始
    while not await bhv.is_round_active():
        await asyncio.sleep(0.5)

    # 组合行为：转向目标 -> 前进 -> 开火
    await bhv.turn_to(pid, 150, 50)        # 面向世界坐标 (150,50)
    await bhv.move_toward(pid, 150, 50)    # 驶向目标
    await bhv.fire(pid, 0.15)              # 开火

    pos = await bhv.get_position(pid)      # get 查询
    print(f'位置: {pos}')
```

### 2.3 运行

```powershell
python my_behavior.py 9222
```

> 前提：Edge 已用 CDP 端口启动并进入游戏（`启动-CDP浏览器.bat` 或 `python launch_cdp.py 9222`）。

### 2.4 先自动开一局本地局（`scripts/start_local_game.py`）

每个控制脚本都依赖"对局中 + 有可控角色"。这一步现在可以一条命令完成：

```powershell
python scripts\start_local_game.py                     # ego 浏览器 + 2 人局（端口 auto）
python scripts\start_local_game.py --players 3         # 3 人局（方向键 / WASD / 鼠标）
python scripts\start_local_game.py --port 9222         # 指定端口
python scripts\start_local_game.py --restart           # 先刷新页面再开局（干净复现）
python scripts\start_local_game.py --json              # 只输出机器可读结果
```

也可以当库用：

```python
from start_local_game import ensure_local_game      # scripts/ 目录
info = await ensure_local_game('auto', players=2)
# info = {port, players, bind, pids, roles, actions, model, inputSets, maze}
```

> ⚠️ **致命坑（必读）**：用菜单处理器**程序化**开 Local 局后，
> `window.Inputs.__metaclass.inputManagers` 是**空数组**——input set
> （`WASDKeys`/`arrowKeys`/`mouse`）没有分配给任何 playerId。
> 于是 `get_roles()` 返回 `{}`、`pick_role()` 拿不到坦克、所有控制脚本报
> "没有可控坦克"。人手点菜单开的局不会遇到（UI 会替你绑定）。
> 脚本的解法是调用游戏自己的分配 API `Inputs._assignInput(playerId, inputSetId)`
> 显式绑定，之后静态角色识别立刻生效、`setInputState` 链路可用。
> 绑定顺序由 `--bind` 决定，默认 `arrowKeys,WASDKeys,mouse`（方向键角色优先）。

> 实测（全新刷新页面）：`pids` 绑定 `arrowKeys`/`WASDKeys` → `roles` 解析为
> `arrows`/`keyboard`，回合状态 in round，迷宫 8x5。

> 拿到真实端口后，再把它传给自己的脚本（`TankBehavior(port=9222)` 只认数字端口）；
> 例如先 `python scripts\start_local_game.py auto --json` 看 `port`，再 `python my_behavior.py 51109`。

## 3. 行为 API 速查（TankBehavior）

### 3.1 连接 / 生命周期

| 方法 | 说明 |
|------|------|
| `TankBehavior(port=9222)` | 构造，port 为 CDP 调试端口 |
| `await connect(url='tanktrouble.com')` | 连接游戏页面 |

### 3.2 可操控角色（GET）

| 方法 | 说明 |
|------|------|
| `await get_roles()` | 全部可控角色 `{playerId: 'keyboard'/'arrows'/'mouse'}` |
| `await pick_role(prefer='keyboard')` | 选一个角色的 playerId（优先 keyboard） |
| `await pick_role_strict(role)` | **严格按控制类型选角色**，找不到返回 None（不回退，用于固定测试变量） |

> ⚠️ 在线多人模式只有**本地玩家的坦克**才有角色绑定；get_roles 返回的才是你能控制的。
> `pick_role_strict('arrows')` 精确拿方向键角色、`pick_role_strict('keyboard')` 拿 WASD 角色。

### 3.3 状态查询（GET）

| 方法 | 返回 |
|------|------|
| `get_tanks()` | `{playerId: {x, y, rot, alive}}` |
| `get_tank(tank_id)` | 单辆坦克状态，或 None |
| `get_round_state()` | `'in round'/'between rounds'/'counting down'/'ended'/'none'` |
| `is_round_active()` | 布尔，是否对局中 |
| `is_alive(tank_id)` | 布尔，是否仍在场 |
| `get_position(tank_id)` | `(x, y)` 米，或 None |
| `get_rotation(tank_id)` | 弧度，或 None |
| `get_maze_size()` | `(width, height)` 米 |
| `get_projectiles()` | 弹丸列表 `[{id,x,y,vx,vy,owner}]` |
| `get_destroyed()` | 本回合已摧毁玩家 id 列表 |
| `get_nearest_wall(tank_id)` | `(wall, dist_m, target_rot)` 最近墙信息 |

### 3.4 地形 / 墙体数据（GET，静态）

| 方法 | 返回 |
|------|------|
| `get_maze_tiles()` | 原始格数据（见下方"数据结构"） |
| `get_wall_segments()` | 全部墙段 `[[x1,y1,x2,y2],...]`（米，含外边界+内部墙） |
| `get_terrain()` | 完整地形摘要（网格+墙段+毒圈一次性获取） |
| `extract_storm_zones(terrain)` | 从地形摘要里**单独筛出毒圈**（纯函数/静态方法） |
| `is_open_tile(tx, ty)` | 格子 `(tx,ty)` 是否可通行 |
| `open_tile_center(tx, ty)` | 可通行格中心世界坐标 `(x,y)`（米） |

**数据结构（重要）**：

```
tiles（get_maze_tiles 返回）:
  {w: 宽(格), h: 高(格),
   tiles: 二维数组 tiles[y][x] = [present, topWall, leftWall]}
   - present (tile[0]) : 1 = 可通行地面格，0 = 封闭格
   - topWall (tile[1]) : 1 = 该格上边界（-y 方向）有墙
   - leftWall(tile[2]) : 1 = 该格左边界（-x 方向）有墙
   ⚠️ 索引顺序是 tiles[y][x]（先 y 后 x，按行遍历）

墙段（get_wall_segments 返回）:
  [[x1, y1, x2, y2], ...]  每条线段端点，单位=米
  包含：外边界 4 条 + 所有内部墙（由 top/left 墙标记推导）

墙的表示规则：
  墙只记录在【面向它的开放格】上——开放格四周若邻接封闭格/地图外，
  则该方向 topWall/leftWall=1。封闭格（present=0）四面都是墙。
  1 格 = 10 米（Constants.MAZE_TILE_SIZE）。
```

> 📌 **读取时机**：地形只在**回合切换**时变化（迷宫重新生成），对局中
> 全程不变 → **每回合开始时读一次即可**，不必每帧读。

### 3.5 毒圈（Radioactive Fog，GET，实时）

| 方法 | 返回 |
|------|------|
| `get_storm_zones()` | 毒圈状态列表（见下） |
| `get_storm_safe_area()` | 当前安全区 tile 范围 `{minX,minY,maxX,maxY}` 或 None |
| `is_in_safe_area(x, y)` | 世界坐标 `(x,y)` 是否在安全区内（米） |

**数据结构（重要）**：

```
毒圈（get_storm_zones 返回的每个元素）:
  {id: 毒圈 id,
   minX, minY, maxX, maxY,          # 地图 tile 边界
   expLeft, expTop, expRight, expBottom,  # 四边已收缩 tile 数
   side}                            # 0=右 1=下 2=左 3=上，-1=步间等待

安全区（可存活区域）tile 范围:
  left   = minX + expLeft
  right  = maxX - expRight
  top    = minY + expTop
  bottom = maxY - expBottom
```

> 📌 **读取时机**：毒圈**随时间动态收缩**（回合开始后出现，持续向内缩），
> 与静态地形不同 → **每次决策都要实时读取**，不能缓存。
> 示例：`terr = await bhv.get_terrain(); zones = bhv.extract_storm_zones(terr)`

### 3.8 弹道 / 火控（ballistics + RayCast）

| 方法 | 说明 |
|------|------|
| `get_walls_cached(refresh=False)` | 获取墙段并缓存（每回合读一次，refresh=True 强制重读） |
| `predict_shot(px, py, angle, tx, ty, radius)` | 判断某角度能否命中目标（含镜面反弹推演） |
| `aim_straight(px, py, tx, ty)` | 直线瞄准方向角 |
| `find_aim_angle(tank_id, target_pos, radius, sample_count)` | tiles 版找命中角（快但墙标记不全，预筛用） |
| `find_aim_angle_raycast(tank_id, target_pos, target_id=None, max_traveled=None, muzzle_offset=0.0, self_radius_slope=0.0, rotated_hit_check=False, exhaustive_fallback=False)` | **权威命中角**（Box2D 物理射线，推荐；`target_id` 传目标坦克 id 可排除穿墙误判）。在 bounces 1~4 的可靠命中角中选 **traveled 最短** 的一条。`max_traveled` 限制弹丸**实际飞行长度**（米，超限即丢弃；严格验收用 45m）。后三个参数是**默认关闭**的调优项：`muzzle_offset`（炮口出膛建模，约 2.0）、`self_radius_slope`（自伤半径随反弹数放宽）、`rotated_hit_check`（本地坐标系命中判定）、`exhaustive_fallback`（预筛无解时全量再扫）——它们会改变可选角集合，**改动后必须重跑 30 回合验收**（见 [04-火控系统](04-火控系统.md)） |
| `find_aim_angle_at(px, py, tx, ty, target_id=None)` | **任意位置**检查能否命中（机动射击位评估，无需坦克在场） |
| `predict_lead_target(tank_id, target_pos, target_id, bullet_speed)` | **移动目标预测**（lead targeting） |
| `aim_and_fire(tank_id, target_pos, raycast=True, lead=False, target_id=None, max_traveled=None, muzzle_offset=0.0)` | 自动火控：瞄准命中角并开火（**武器感知**：加特林自动延长按住+适配弹速；`lead=True` 启用移动目标预测，需传 `target_id`；`max_traveled` / `muzzle_offset` 等透传给 `find_aim_angle_raycast`） |
| `get_active_weapon(tank_id)` | 查询坦克当前武器类型（-1基础/0激光/1双管/2霰弹/3导弹/4地雷/5加特林） |
| `suicide_by_bounce(tank_id)` | 朝最近外墙开火自杀（弹丸反弹自伤，用于结束本地局回合） |

**物理参数（ballistics 模块，源码+实测确认）**：

```
BULLET_SPEED   = 18.0 m/s  炮弹恒定速度（update() 每帧强制）
BULLET_LIFETIME= 10.0 s    弹丸最大存活时间
MAX_BOUNCES    = 5         最大反弹次数
TANK_RADIUS    = 2.0 m     坦克命中半径（3x4m 矩形近似）
MAZE_TILE_M    = 10.0 m    每格尺寸
WALL_HALF_THICK= 0.4 m     墙半厚（Box2D 实测墙厚 0.8m）
```

**弹道规则**：
- 直线飞行，速度恒 18 m/s
- 撞墙 = 理想镜面反射（入射角 = 反射角）
- 反弹 5 次或存活 10 秒后消亡

**⚠️ 墙段数据源（重要经验）**：
- `get_wall_segments()`（tiles 推导）**不完全可靠**：tiles 的墙标记与真实
  Box2D 碰撞墙有偏差（缺失墙/虚假墙），导致反弹路径预测不准。
- **权威方案 = Box2D RayCast**：用游戏物理世界的 `World.RayCast()` 做链式
  反弹推演，命中判定与真实弹道一致。
- `ballistics.inflate_walls()` 把中心线墙膨胀成 ±0.4m 碰撞面，可补偿墙厚。

**RayCast 火控关键修复（实测 30 回合全击杀验证）**：
1. **穿墙误判（最关键）**：RayCast callback 若无条件记录所有相交坦克
   （含被墙挡住的），会误报"命中"而实际弹丸先撞墙反弹偏出。必须
   **只保留最近的碰撞点**（墙在前则坦克不算命中）。
2. **官方弹道算法**：直接用游戏 `B2DUtils.calculateProjectilePath`
   （AI/服务器同款），与真实弹丸物理零误差。
3. **选 bounces 1~4 + 最短旅行距离（决定能否 30 连杀）**：枚举所有
   可靠命中角（bounces 1~4，排除自伤/擦边），选【traveled 最短】一条。
   - 路径越短 → 飞行时间越短 → 越不易错过移动目标（配合 lead 预判）
   - 路径越短 → 越不易反弹回射手自身 → 降低自杀风险
   避免打太长/太绕的多反弹角（实测失败集中于长 traveled 路径）。
4. **穿透/擦边检查**：官方射线是零宽，弹丸有 0.25m 半径，擦边时实际
   不命中。验证弹丸【中心路径】是否真正进入坦克矩形（半宽1.75×半高2.25，
   即坦克矩形+弹丸半径）——**必须在坦克本地坐标系里判定**（用目标
   `get_rotation()` 旋转入射点）；用轴对齐盒子会把"斜着的坦克"上真实可
   命中的入射点误判为擦边丢掉，导致本可命中的回合被判"无解"。
5. **自伤检查（path_hits_self，防自杀）**：坦克是可旋转 3×4m 矩形
   （角顶到中心 2.5m）+ 弹丸半径；但官方射线(零宽)与真实弹丸(有半径)
   在坦克转向/目标移动时有偏差，且**每次反弹都会累积**（实测 3 次反弹可偏
   >2m：预测路径离射手 4m+ 判"安全"，真实回程却在 1.8m 处把自己打死）。
   → 自伤半径按反弹次数放宽：`min(4.0 + 1.0×反弹数, 8.0)`，任何回程进入
   该范围即拒绝，宁可不开火换位也绝不自杀。（30 连杀无自杀的直接原因）
6. **飞行长度上限（max_traveled）**：多反弹路径越长 → 偏差越大、飞行时间越长
   （移动目标越容易躲开）。严格验收脚本用 `MAX_TRAVELED=45.0`（米）：
   超过即认为"此处无解"，改为机动换位，而不是打一发 60m+ 的祈祷弹。
7. **防超圈转向**：游戏 getRotation() 是累积值（可到几百上千度）。
   用归一化 [-π,π) 计算转向方向会在 ±180° 边界跳变、选错方向→绕远路
   →超圈→弹丸方向错。**直接读未归一化原始累积角**，把目标换算成最近
   的累积等效角再转向（误差实测 ≤1.7°，不超圈）。
8. **最终朝向校验**：转向后若朝向与目标差 >2°，不开火（避免废弹）。
9. **选角兜底**：tiles 预筛用的墙标记与真实 Box2D 墙有偏差，可能整体漏掉
   真实解 → 预筛无解时自动做一次**全量角度权威扫描**再判"无解"。

**火控方法（推荐组合）**：
```
find_aim_angle_raycast(tank_id, target_pos, target_id=目标id, require_bounce=True)
    # 返回选中的命中角：bounces 1~4 内 traveled 最短；无解返回 None
aim_and_fire(tank_id, target_pos, raycast=True, lead=True, target_id=目标id)
    # 自动转向+停稳+朝向校验+开火；lead=True 启用移动目标预判
suicide_by_bounce(tank_id)  # 无解/捡到非基础弹武器时自杀结束回合（武器感知）
```

**武器感知（加特林预热）**：加特林（type5）按住 0.5s 才出弹，松扳机 1.5s
放电归零。瞬时点射打不出子弹。`aim_and_fire` 自动检测加特林：按住时间
延长到 ≥0.7s，弹道预测用 27.5m/s 弹速。`suicide_by_bounce` 同理加特林
需按住 0.7s 出弹反弹自伤。

**机动火控模式**（打不到就移动找射击位）：
```python
# 伪代码：若当前位置无命中角，导航到目标周围候选射击位再打
ang = await bhv.find_aim_angle_raycast(attacker, target_pos, require_bounce=True)
if ang is None:
    await bhv.navigate_to(attacker, 候选射击位, arrival=2.0)  # 绕迷宫移动
    # 到新位置后重新找角开火
```

> 📌 火控是"算法派"核心：弹道是确定性物理，可用官方弹道精确推演。
> ✅ **严格验证已通过**：`fire_verify_strict.py` 方向键打 WASD 角色，
> **连续 30 回合全部有击杀**（bounces 1~4 中选 traveled 最短角，距离 ≤32m，≥15m），
> 无自杀、无打队友。验证脚本含自杀检测（击杀数未增但对面胜利数增 =
> 自杀，算火控缺陷）、无解回合自杀跳过（不计入）、武器感知（非基础弹
> 自杀跳过）。

### 3.9 导航（迷宫寻路）

| 方法 | 说明 |
|------|------|
| `plan_maze_path(ctl, start_xy, end_xy)` | 迷宫格子路径（游戏 `getShortestPathWithGraph`） |
| `maze_distance(ctl, from_xy, to_xy)` | 迷宫 Dijkstra 距离（格数） |
| `navigate_to(tank_id, target_xy, arrival=1.5)` | **迷宫寻路导航**（绕墙 + 卡墙沿墙滑行） |

**说明**：
- `navigate_to` 每步前进前校正朝向，卡墙时沿墙滑行绕开，每个航点后
  重新规划（防累积偏离）。比 `move_toward`（直线撞墙）可靠得多。
- 游戏自带寻路（`getShortestPathWithGraph` + Dijkstra 距离场），
  直接调用权威 API，无需自己实现 A*/Dijkstra。

**示例（机动火控：打不到就移动找射击位）**：
```python
if await bhv.find_aim_angle_raycast(attacker, target_pos) is None:
    await bhv.navigate_to(attacker, (tx+8, ty), arrival=2.0)  # 绕迷宫移动
    await bhv.aim_and_fire(attacker, target_pos, raycast=True, lead=True, target_id=target)
```

> 📌 游戏导弹也用寻路制导（HomingMissile 用 Dijkstra 距离场选目标 +
> `getShortestPathWithGraph` 逐格追踪绕墙）——这是"算法派"思想的官方印证。

## 4. ⚠️ 核心红线（务必读）

### 4.1 在线模式 = 服务器权威，必须走 setInputState

```
✗ 错误：tank.setForward(true) / tank.setRotation(...)
   只改本地对象，不发服务器 -> 下一帧回弹（rubber-banding）、开火无效

✓ 正确：TankCtl.set_input() / 本模板所有 set 方法
   InputState.withState(...) -> gc.setInputState -> emitTankState（发服务器）
   与真实键盘输入完全同路径
```

**结论**：写行为一律用模板提供的 set 方法，不要直接调游戏对象方法。

### 4.2 转向符号（已实测）

- **RIGHT 增大 getRotation()**，**LEFT 减小**。
- 需要旋转值变大（diff>0）→ 用 `turn_right`；变小 → `turn_left`。
- 计算夹角用 `wrap_pi(target - cur)` 归一化到 [-π, π)。

### 4.3 迷宫与地形读取时机（地形 vs 毒圈）

- **地形（tiles/walls/尺寸）**：只在**回合切换**时变化 → **每回合开始读一次即可**，
  可缓存到本回合结束。通过 `get_round_state()` 检测到 'in round' 时刷新。
  但注意：**每回合尺寸/布局都会变**，切回合后必须重读，否则距离算负数。
- **毒圈（storm zones）**：**随时间动态收缩** → **每次决策实时读取**，
  不能缓存。AI 移动前用 `is_in_safe_area()` 检查是否还在安全区。

### 4.4 回合状态用权威源

- 用 `get_round_state()`（底层 `GameModel.getState()`）。
- 不要依赖 `addRoundEventListener` 事件 hook：页面刷新后丢失、签名易错。

### 4.5 坦克存活判断

- 没有 `isAlive()` 方法。判断"是否在场"看 `getTanks()` 里有没有该 id。
- 死亡后可能留下"冻结尸体"（对象仍在但不动）：位置连续多次不变可视为已死。

1. **复制模板** → `copy tank_behavior_template.py my_script.py`
2. **连接 + 拿角色**：`connect()` → `get_roles()` / `pick_role()`

4. **写行为主循环**：
   ```python

       await bhv.move_toward(pid, tx, ty)
       await bhv.fire(pid)
       await asyncio.sleep(0.2)
   ```

   - 持续自杀 → `loop_suicide.py`
   - 寻路/卡墙 wiggle → `pickup_mine.py` 的 `Navigator`

## 7. 常见问题（FAQ）

**Q: 运行脚本报 "no tanks" / "没有可控坦克"？**
游戏页面没就绪、不在对局、或该实例上没有本地坦克。先用 `tt.py ping 9222` 确认。

**Q: 坦克不受控制（回弹 / 开火无效）？**
你用了直接 setter（第 4.1 节红线）。改用模板的 set 方法。

**Q: 转向总是转反方向？**
符号搞反了（第 4.2 节）：需要更大旋转值用 turn_right。

**Q: 距离变成负数？**
切回合后迷宫尺寸变了但缓存了旧值（第 4.3 节）：每次回合开始重读 `get_maze_size()`/`get_terrain()`。

**Q: 毒圈安全区不准 / 没变化？**
毒圈是动态收缩的（第 4.3 节）：必须实时读取 `get_storm_zones()`，不能缓存。地形才适合回合一次读取。

**Q: 坦克位置算错格？**
tiles 索引是 `tiles[y][x]`（先 y 后 x）；坐标转格子用 `int(x / 10)`、`int(y / 10)`（每格 10 米）。

**Q: 回合切换后角色/状态丢失？**
用权威源（第 4.4 节）：`get_roles()` / `get_round_state()` 都是权威静态读取，刷新后依然正确。

**Q: 脚本卡住不动？**
检查是否死循环等待回合开始（回合之间会等数秒）；检查 `turn_to`/`move_toward` 安全上限（60/80 次迭代）是否触底。
