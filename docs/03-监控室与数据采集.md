# TankTrouble 持续自杀 + 数据录制 — 使用指南

> 环境说明：本篇的 bat 实测记录来自 **Windows 环境**；Linux 请用对应的 `.sh` 脚本，
> 详见 [20-Linux适配.md](20-Linux适配.md)。

> 覆盖：`loop_suicide.py`（所有可控角色自杀）+ `recorder.py`（数据录制）
> 支持：本地局（3 角色）、在线多人（本地玩家）

---

## 1. 它能做什么

- **所有可操控角色自杀**：读取游戏输入管理器（`window.Inputs.__metaclass.inputManagers`），
  对 keyboard/arrows/mouse 全部本地可控坦克执行**贴墙点射自杀**（弹丸出膛 2.5m→贴墙反弹→瞬间自伤）
- **循环往复**：自杀→等待重生→下一回合再自杀
- **数据录制**：完整游戏状态快照（坦克/弹丸/道具/地雷/墙体/毒圈/角色/比分/回合）写 JSONL
- **在线多人**：只操控本地玩家的坦克（远程玩家不受影响）

---

## 2. 前置条件

1. Edge CDP 实例已启动并进入游戏
   - 本地局：`python tt.py farm N` 或手动开 Local game
   - 在线：浏览器登录进入多人房间
2. 依赖：Python 3.13 + websockets（已在 tanktrouble_ai 环境）

## 3. 启动流程

### 3.0 双击即用（推荐）

直接双击 `tanktrouble_ai` 目录下的 bat 文件：

| 文件 | 功能 | 改参数位置 |
|------|------|-----------|
| `启动-持续自杀录数据.bat` | 监控室 + 所有角色自杀 + 录制 | 文件顶部 `set TT_PORT=...` 等 |
| `启动-仅持续自杀.bat` | 只自杀（观战） | `set TT_PORT=...` |
| `启动-监控室.bat` | 只开监控室 | 实例数/端口 |

> 前提：Edge CDP 实例已启动并进入游戏。
> 停止：Ctrl+C（自杀脚本）；关闭 "TT-Monitor" 窗口（监控）。

### 3.1 手动（本地局）

```powershell
cd "D:\AI Agent\tanktrouble_ai"

# 最简单：所有可控角色自杀，不录制
python scripts\loop_suicide.py 9222

# 自杀 + 录制数据
python scripts\loop_suicide.py 9222 --record data.jsonl --fps 20
```

### 3.2 完整流程（从零开始）

```powershell
# 1) 启动 CDP 实例（2 个）
cd "D:\AI Agent\tanktrouble_ai"
python tt.py farm 2

# 2) 自动开 Local 局并绑定控制角色（不再需要手点菜单/坐标）
python scripts\start_local_game.py 9222 --players 2
python tt.py list          # 查看实例

# 3) 启动监控室（可选，看画面；与各 .bat 启动器一致：3 CDP + 1 TM；
#    只有 2 个 CDP 时第三个卡片显示"离线"并自动重连）
python monitor_server.py 3 9222 --tm 1
# 状态端口 9310(CDP 9222)/9311(9223)/9312(9224)/9313(TM)，TM 推送端口 9301
# 浏览器打开 tanktrouble_monitor.html

# 4) 启动持续自杀（所有可控角色）
python scripts\loop_suicide.py 9222 --record data\train_data.jsonl --fps 20
```

### 3.3 在线多人模式

```powershell
# 在已登录多人房间的 Edge 实例上运行
python scripts\loop_suicide.py 9223 --record online_data.jsonl --fps 20
# 脚本自动识别本地玩家（inputManagers 只含本地绑定），只自杀自己的坦克
```

## 4. 参数说明

| 参数 | 默认 | 说明 |
|------|------|------|
| `port` | 9222 | CDP 端口；也接受 **`auto`**（自动发现 ego 浏览器/扫描 9222–9231），或环境变量 `TT_CDP_PORT` |
| `--record 文件` | 关 | 录制状态到 JSONL（默认**覆盖**文件；追加需 `--append`） |
| `--fps N` | 20 | 录制帧率 |
| `--compress` | 关 | 压缩录制：地形只在回合切换时写一次，其余帧只存动态数据 |
| `--allow-teleport` | 关 | **no-op 兼容参数**，仅打印一行提示；传送已永久禁用（见 6.1） |

## 4.1 状态快照字段（`monitor_server.STATE_JS`，v6.6）

监控/录制/回放共用同一快照 JS，一次 `Runtime.evaluate` 返回：

```
t_ms / raf_frame / raf_ts / phase / roundId / mode / gameId / countdown(仅 counting down) / countdown_raw / theme / theme_name
active(=phase=='in round') / roundActive / betweenRounds / countingDown / alive / winner
paused / game_time_ms / hidden
tanks: {pid: {x,y,rot,angle,alive,weapon,shield,shieldLife,vx,vy}}
       # vx_fd/vy_fd/speed_fd/omega_fd 由 ttprim.state() 派生（原始 /state 不含）
projectiles: [{id,x,y,vx,vy,owner,type,timeAlive,lifetime,maxLifetime,deadlyToOwner}]
collectibles / mines / zones(毒圈完整字段，v6.5) / walls(去重+排序) / maze:{w,h,cells} / roles
storm(本轮是否启用毒圈) / storm_active(毒圈是否已出现) / storm_zone_count / allPlayerIds
scoresKill / scoresVict
```

使用注意（实测，详见 [27-监控get接口黑盒测试](27-监控get接口黑盒测试-2026-10-26.md)）：

- `vx/vy` 是 Box2D 速度，实测会陈旧/冻结（40% 在动样本为 0）→ 提前量用 `ttprim` 的 `vx_fd/vy_fd`；
- `active` 旧实现恒 false（`gc.isRoundActive()` 恒 false），v6 改为由 `phase` 推导；
- `countdown` 只在 `phase=='counting down'` 时有效；in round 时旧值 3 会残留（v6 置 null）；
- `scoresVict` 在 between rounds 才更新，比 `scoresKill` 晚 **~2.9–3.0s**（不是 0.5s）；
- 死亡坦克会从 `tanks` 整个消失；`winner` 恒 null；
- `walls`（v6.3 修复）：只含**可碰撞墙**——每格（含 void 格）的 `topWall/leftWall` 标志，已去重+稳定排序；
  旧规则会给“两侧都是 void”的边生成幽灵墙（不渲染、无碰撞体）。地图外边界可能另有 1–4 条
  “只渲染、不碰撞”的描边，不在 `walls` 内；`maze.cells[x][y]=[present,topWall,leftWall]` 可恢复 floor/void。
- 无相机变换/主题贴图/仿真时间/事件流；`paused/game_time_ms` 用于检测窗口失焦导致的游戏暂停。
- `raf_frame`（渲染帧计数，每 rAF +1）/ `raf_ts`（该帧 Date.now）：v6.4 新增，用于动态测试把 state
  对齐到最近渲染帧（后台/暂停时 rAF 不前进）；截图中逐对象绘制时刻仍不可得。
- `zones`（v6.5）：毒圈只在**在线房间**出现；每项含 `safeTile`/`safe`（世界米）/`tileBounds`/
  `expansionTiles`/`expansionSide`/`expansionTime`/`expansionSequence`；经典模式 ~60s 出现、每 10s 缩一整行/列。
  `safe` 是整数 tile 目标边界；**v6.6 新增 `safeSmooth`**（步内连续插值：活跃边 consumed=max(0,count-1+frac)，
  frac=1-expansionTime/10，世界米），用于和画面毒圈雾对齐（雾边缘有 ±1.5~2m 贴图波动）。
  **两相/锯齿**：10s 周期=等待相(expT 10→5, `expansionSide=-1`, safeSmooth==safe)+主动相(expT 5→0, side=seq[k-1])；
  像素验证/采样判别窗口用 **mid(expT 4.0–5.2)**（early/late 几何差太小分不出 smooth）；回合结束 `zones` 会同一采样清空（不是 safeTile 渐零）。
  ⚠️ `storm` 只表示本轮是否启用毒圈（在线局常为 true），**毒圈是否已出现看 `storm_active`/`zones`**。
- `mode`/`gameId`（v6.5）：`client online`/`client local` 与在线房间 id（本地局 gameId=null）。
- `countdown_raw` 是模型原始 `countDownValue`，in round 时也可能残留 3（v6 起 `countdown` 仅在 counting down 有效）；
- `theme`/`theme_name`：地图主题 id/名（0=STANDARD 无装饰、1=HALLOWEEN、2=CHRISTMAS、3=COUNT、4=RANDOM 每回合随机）。
  本地局默认 RANDOM，截图/像素分析会受装饰与墙体画法影响；要复现可 `gc.setTheme(0)` 或
  `python scripts/start_local_game.py auto --players 2 --restart --theme 0` 固定 STANDARD。
- 本地局网站会盖一层 `ControlsOverlay`（按键设置）DOM 浮层；隐藏它只做 CSS
  （`#overlay` 透明 + `.controls{display:none}`），**不要** `ControlsOverlay.hide()/popOverlay()`
  （实测会破坏 Game scene 渲染顺序，坦克被地板盖住）。

**本地局"按键设置"遮罩**：`scripts/start_local_game.py` 开局后会自动把 `#overlay` 灰暗背景改透明、
隐藏 `.controls` 表单（之前会一直盖住真实画面）。手动执行：`VisualPrim.hide_ui_overlay()`。

## 6. 常见问题

### 6.1 坦克卡墙/越界
**脚本不会传送坦克**：传送默认禁用，`--allow-teleport` 只是为兼容旧启动脚本保留的 no-op。
真实自杀路径：用 `gameutils.find_nearest_wall` 算出最近的墙（外墙 **或** 内部迷宫墙）→
转向正对墙 → 驱动到离墙约 **3 m** → 开火；弹丸出膛约 2.5 m，垂直撞墙后反弹回自身完成自伤。
若转向未收敛（朝向误差未进容差）就**不开火**，留到下一轮重试，避免把弹丸射偏飞走。

### 6.2 坦克死了但对象还在（frozen）
无 `isAlive` 方法。脚本用 `gameutils.tank_alive`（坦克 id 是否仍在 `getTanks()` 里）判断在场；
对象残留但已死时表现为**位置停滞**，`suicide_once` 用"连续采样位置不变"判定死亡。
（不是速度判活——`velocity>0` 的旧说法已不成立。）

### 6.3 在线模式看不到角色
输入管理器只在"本地输入绑定"时创建。确认你已进入游戏且用的是
WASD/方向键/鼠标（三者至少一个）。远程玩家不在 inputManagers 里（正常）。

### 6.4 想只自杀特定角色
暂不支持过滤；当前策略是"所有可控角色都自杀"。如需单角色，
可临时注释 main 循环里的角色或用 tankctl 手动控制。


### 8.2 本轮修补

| 问题 | 修复 |
|---|---|
| `record_only.py` 只接受数字端口，`auto` 会回落 9222 → 连不上（超时） | 支持 `auto`（`ego_browser.resolve_port`）；`fire_control/fire_record/fire_verify(_strict)/loop_suicide` 一并支持 |

| 监控室页面显示"加载中"但无数据 | 实测确认是"游戏页被同一标签页导航走"导致，非页面 bug；独立标签页下 9310 实时 + 9315 回放均正常渲染 |

| `启动-监控室.bat` | ✅ | `ensure_browsers.py` 检测复用在线实例 → 启动 monitor_server → WS 9310 `err=None tanks=2`；`TT_SKIP_OPEN` 生效 |
| `重启-监控室.bat` | ✅ | 先 kill 残留再启动，全流程跑通 |
| `启动-仅录制.bat` | ✅ | 录到 789 帧 / 624KB（20fps，压缩格式） |

**本轮修复**：

1. **`启动-监控室.bat` / `重启-监控室.bat` 原本是坏的**：里面用跨多行的
   `python -c "..."` 嵌入脚本——批处理逐行解析，必然报错。已改为调用
   `scripts/ensure_browsers.py`（新增，跨平台）。
2. `timeout /t N /nobreak >nul` 在 stdin 被重定向时直接报错（非交互/CI 场景）。
   已换成 `ping -n N+1 127.0.0.1 >nul`。
3. bat 端口可被环境变量覆盖：`TT_CDP_PORT=<端口>`；监控页可用
   `TT_SKIP_OPEN=1` 跳过自动打开；`TT_MONITOR_PORTS` 可用 `CDP_PORTS` 覆盖。
4. 其余 bat 的 `%~dp0` 相对路径已验证可移植（不依赖本机目录）。

**sh 脚本**（Linux/macOS，无法在 Windows 直接执行）：用 WSL 内真实 POSIX `sh -n` 做了语法检查，
4 个脚本全部 `SYNTAX-OK`；并确认 LF 换行（`.gitattributes` 保证）、脚本内引用的文件均存在、
`setup-linux.sh` 已改为 venv 安装（规避 PEP 668 `externally-managed-environment`），
其它脚本自动激活 `.venv`。
