# TankTrouble 持续自杀 + 数据录制 — 使用指南

> 覆盖：`loop_suicide.py`（所有可控角色自杀）+ `recorder.py`（数据录制）
> 支持：本地局（3 角色）、在线多人（本地玩家）

---

## 1. 它能做什么

- **所有可操控角色自杀**：读取游戏输入管理器（`window.Inputs.__metaclass.inputManagers`），
  对 keyboard/arrows/mouse 全部本地可控坦克执行**贴墙点射自杀**（弹丸出膛 2.5m→贴墙反弹→瞬间自伤）
- **循环往复**：自杀→等待重生→下一回合再自杀
- **数据录制**：完整游戏状态快照（坦克/弹丸/道具/地雷/墙体/毒圈/角色/比分/回合）写 JSONL
- **在线多人**：只操控本地玩家的坦克（远程玩家不受影响）

---

## 2. 前置条件

1. Edge CDP 实例已启动并进入游戏
   - 本地局：`python tt.py farm N` 或手动开 Local game
   - 在线：浏览器登录进入多人房间
2. 依赖：Python 3.13 + websockets（已在 tanktrouble_ai 环境）

---

## 3. 启动流程

### 3.0 双击即用（推荐）

直接双击 `tanktrouble_ai` 目录下的 bat 文件：

| 文件 | 功能 | 改参数位置 |
|------|------|-----------|
| `启动-持续自杀录数据.bat` | 监控室 + 所有角色自杀 + 录制 | 文件顶部 `set TT_PORT=...` 等 |
| `启动-仅持续自杀.bat` | 只自杀（观战） | `set TT_PORT=...` |
| `启动-监控室.bat` | 只开监控室 | 实例数/端口 |

> 前提：Edge CDP 实例已启动并进入游戏。
> 停止：Ctrl+C（自杀脚本）；关闭 "TT-Monitor" 窗口（监控）。

### 3.1 手动（本地局）

```powershell
cd "D:\AI Agent\tanktrouble_ai"

# 最简单：所有可控角色自杀，不录制
python scripts\loop_suicide.py 9222

# 自杀 + 录制数据
python scripts\loop_suicide.py 9222 --record data.jsonl --fps 20
```

### 3.2 完整流程（从零开始）

```powershell
# 1) 启动 CDP 实例（2 个）
cd "D:\AI Agent\tanktrouble_ai"
python tt.py farm 2

# 2) 自动开 Local 局并绑定控制角色（不再需要手点菜单/坐标）
python scripts\start_local_game.py 9222 --players 2
python tt.py list          # 查看实例

# 3) 启动监控室（可选，看画面；与各 .bat 启动器一致：3 CDP + 1 TM；
#    只有 2 个 CDP 时第三个卡片显示"离线"并自动重连）
python monitor_server.py 3 9222 --tm 1
# 状态端口 9310(CDP 9222)/9311(9223)/9312(9224)/9313(TM)，TM 推送端口 9301
# 浏览器打开 tanktrouble_monitor.html

# 4) 启动持续自杀（所有可控角色）
python scripts\loop_suicide.py 9222 --record data\train_data.jsonl --fps 20
```

### 3.3 在线多人模式

```powershell
# 在已登录多人房间的 Edge 实例上运行
python scripts\loop_suicide.py 9223 --record online_data.jsonl --fps 20
# 脚本自动识别本地玩家（inputManagers 只含本地绑定），只自杀自己的坦克
```

## 4. 参数说明

| 参数 | 默认 | 说明 |
|------|------|------|
| `port` | 9222 | CDP 端口（**只接受数字**，写 `auto` 会回退到 9222） |
| `--record 文件` | 关 | 录制状态到 JSONL（默认**覆盖**文件；追加需 `--append`） |
| `--fps N` | 20 | 录制帧率 |
| `--compress` | 关 | 压缩录制：地形只在回合切换时写一次，其余帧只存动态数据 |
| `--allow-teleport` | 关 | **no-op 兼容参数**，仅打印一行提示；传送已永久禁用（见 6.1） |

---

## 5. 输出/验证

- 控制台：`round state` / `controllable tanks` / 每次自杀日志
- 录制文件：每行一个 JSON 快照 `{"t":"相对秒","wall_t":...,"s":{完整状态}}`
  （`--compress` 时另带 `mv` 迷宫版本号，`maze/walls/zones` 只在地形变化那几帧出现）
- 监控室可实时看到坦克死亡/重生

## 6. 常见问题

### 6.1 坦克卡墙/越界
**脚本不会传送坦克**：传送默认禁用，`--allow-teleport` 只是为兼容旧启动脚本保留的 no-op。
真实自杀路径：用 `gameutils.find_nearest_wall` 算出最近的墙（外墙 **或** 内部迷宫墙）→
转向正对墙 → 驱动到离墙约 **3 m** → 开火；弹丸出膛约 2.5 m，垂直撞墙后反弹回自身完成自伤。
若转向未收敛（朝向误差未进容差）就**不开火**，留到下一轮重试，避免把弹丸射偏飞走。

### 6.2 坦克死了但对象还在（frozen）
无 `isAlive` 方法。脚本用 `gameutils.tank_alive`（坦克 id 是否仍在 `getTanks()` 里）判断在场；
对象残留但已死时表现为**位置停滞**，`suicide_once` 用"连续采样位置不变"判定死亡。
（不是速度判活——`velocity>0` 的旧说法已不成立。）

### 6.3 在线模式看不到角色
输入管理器只在"本地输入绑定"时创建。确认你已进入游戏且用的是
WASD/方向键/鼠标（三者至少一个）。远程玩家不在 inputManagers 里（正常）。

### 6.4 想只自杀特定角色
暂不支持过滤；当前策略是"所有可控角色都自杀"。如需单角色，
可临时注释 main 循环里的角色或用 tankctl 手动控制。
