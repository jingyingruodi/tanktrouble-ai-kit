# 12 · 计分与奖励规则（Last Tank Standing / Deathmatch）

> 2026-10-16 摸清。方法：**打包代码里读规则** + **本地两人局里造真实事件实测**。
> 工具：`scripts/probe_score_rules.py`（用游戏自己的 `TankKilledMessage` + `gc.killTank` 触发，
> 走的就是游戏内部的计分路径）。

## 1. 分数结构

| 项 | 内容 |
|----|------|
| 分数条目 | 每名玩家**两条**：`SCORE_TYPES.KILL = 0`、`SCORE_TYPES.VICTORY = 1`，初值均为 **0** |
| 数据结构 | `ScoreState = {id, playerId, type, value}`（`zs.withState(id, playerId, type, value)`） |
| 读取 | `gc.getScores()` / `gc.getScore(id)` / `gc.getScoreByPlayerIdAndType(pid, type)` |
| 修改 | `gc.setScore(id, v)` / `gc.adjustScore(id, ±Δ)`（内部都是 `setScoreState(new State)`） |
| 初始化 | 模式处理器 `getScoreStates(playerId)` 返回 KILL=0 与 VICTORY=0 两条 |

```js
// 源码（打包代码）
getScoreStates(e){ return [zs.withState(Pt.generate("s"), e, SCORE_TYPES.KILL, 0),
                           zs.withState(Pt.generate("s"), e, SCORE_TYPES.VICTORY, 0)] }
```

## 2. ★ 计分规则（核心）

```js
roundEventHandler(e, t, i, a) {
  switch (i) {
    case ROUND_ENDED: {
      const n = e.gameController.getScoreByPlayerIdAndType(a.getPlayerIds()[0], SCORE_TYPES.VICTORY);
      n && e.gameController.adjustScore(n.getId(), 1);          // 回合结束 → 胜者 VICTORY +1
      break;
    }
    case TANK_KILLED: {
      e.roundFinishingDuration = ROUND_FINISHING_DURATION;
      if (a.getKillerPlayerId() !== a.getVictimPlayerId()) {    // ★★ 关键判定
        const n = e.gameController.getScoreByPlayerIdAndType(a.getKillerPlayerId(), SCORE_TYPES.KILL);
        n && e.gameController.adjustScore(n.getId(), 1);        // 击杀者 KILL +1
      }
      break;                                                    // ← 自杀：直接跳出，谁都不加分
    }
    case TANK_DESTROYED: e.roundFinishingDuration = ROUND_FINISHING_DURATION; break;
  }
}
```

**规则表**：

| 事件 | 条件 | 结果 |
|------|------|------|
| 坦克被击毁 | `killerPlayerId != victimPlayerId` | **击杀者 KILL +1** |
| 坦克被击毁 | `killerPlayerId == victimPlayerId`（自杀） | **无人加分、也无人扣分**（无惩罚） |
| 回合结束 | 最后存活者 | **VICTORY +1** |
| 其它玩家 | — | 不变 |

**没有**"自杀扣分"这回事——自杀的唯一代价是**把 VICTORY 让给别人**（你不存活了，最后存活者拿 VICTORY）。

## 3. 实测证据（本地两人局，`probe_score_rules.py`）

```
初始        : A{0:0,1:0}  B{0:0,1:0}  C{0:0,1:0}        （0=KILL, 1=VICTORY）

用例1 击杀   : A 杀 B（killer≠victim）
  前 A{0:0,1:0} → 后 A{0:1,1:0}      ★ KILL +1 ✅   B/C 不变
用例2 自杀   : A 自杀（killer==victim）
  前 A{0:1,1:0} → 后 A{0:1,1:0}      ★ 无变化 ✅（无加分、无扣分）
  （同时：A 死后 C 成为最后存活者 → C 拿到 VICTORY +1）
用例3 清场   : A 活着，杀掉 B 与 C
  前 A{0:1,1:0} → 后 A{0:3,1:1}
      KILL +2（两次击杀各 +1） ✅   VICTORY +1（最后存活者）✅   B/C 不变
```

⚠️ **实测注意**：本地模式下**回合没开始前 `killTank` 会被拒绝**
（源码：`"Attempt to kill tank while round was not started"`），
所以实测必须等 `model.getState() === 'in round'`；用 `probe_score_rules.py` 已内置等待。

## 4. 模式与相关参数

```
GAME_MODE_NAME_INFO = ["Last Tank Standing", "Boot Camp", "Deathmatch"]
                      ↑ mode 0（当前，Scrapyard 主题 / "never-ending"）
                                                   ↑ mode 1（离线教学）  ↑ mode 2（在线）
GAME_MODES = {CURRENT:-1, CLASSIC:0, BOOT_CAMP:1, DEATHMATCH:2, ...}
```

| 常量 | 值 | 含义 |
|------|----|------|
| `SCORE_TYPES` | `{KILL:0, VICTORY:1}` | 两种分数 |
| `EMBLEM_TYPES` | `{TERMINATOR:0, DOMINATOR:1}` | 两种徽章 |
| `DEATHMATCH_ROUND_DURATION` | 60 | Deathmatch 每回合 **60 秒**（"Most kills in 60 seconds"） |
| `DEATHMATCH_RESPAWN_DURATION` | 1 | 死后 1 秒重生 |
| `DEATHMATCH_STORM_APPEAR_DURATION` | 30 | 30 秒开始缩圈 |
| `JOIN_PRIORITY_DEATHMATCH_MIN/MAX_SECONDS_TO_PENALISE` | 10 / 30 | 中途加入 Deathmatch 的**排队惩罚窗口**（秒） |
| `JOIN_PRIORITY_DEATHMATCH_TIME_WEIGHT` | 10 | 上述惩罚的权重 |
| `ROUND_FINISHING_DURATION` | — | 回合结束前的收尾时长（击杀/清场时设置） |

## 5. 徽章（Emblem）由服务端发放

* 客户端**只负责显示**：`SCORE_CATEGORIES = {EMBLEM:0, SCORE:1, SEPARATOR:2, TEAM:3}`，
  `GAME_MODE_SCORE_ITEM_INFO` 决定记分板布局（如 `EMBLEM(TERMINATOR) | KILL | —— | VICTORY | EMBLEM(DOMINATOR)`）；
* 客户端里有 `addEmblem/removeEmblem/getEmblemByPlayerIdAndType`，但**找不到发放条件的判定代码**
  → 徽章（终结者/统治者）由**服务端**按战局统计发放，客户端收到 `EmblemState` 后显示。

## 6. 与分数相关的其它奖励通道（不要混淆）

* **经验（XP）**：`TankKilledMessage` 除 victim/killer 外还带 `experience`，
  以及 `deadlyId` / `deadlyType`（致死来源）→ 击杀另有经验结算；
* **金币（Gold）**：回合状态带 `getVictoryGoldAmount()` / `setVictoryGoldAmount()` / `getGoldSpawnCount()`，
  是**独立于分数**的经济系统（胜利金币 + 场上金币刷新）；
* **押注（Stakes）**：`setStakes/getStake/getStake`（controller/model/roundController 三层），
  用于 ranked/押注局。

## 7. 对 AI 训练/自动化项目的含义

1. **奖励信号**可用 `getScoreByPlayerIdAndType(pid, KILL|VICTORY)` 直接读，无需自己统计击杀；
2. **自杀不扣分**（只是白送对手 VICTORY）→ 自伤规避的动机来自"送对方胜利"而不是扣分，
   设计 reward shaping 时要注意这一点（可以把"自杀"视为等价于"自己出局 + 对手 +1 VICTORY"）；
3. **KILL 与 VICTORY 是两种分数**，Last Tank Standing 下 VICTORY 才是真正决定胜负的量
   （`KILL` 只是击杀数统计）→ 训练目标若只看 KILL 会跑偏；
4. 记录数据集时，`ScoreState` 可直接作为奖励/状态特征（见 `cdp_tools/recorder.py` 的录制管线）。
