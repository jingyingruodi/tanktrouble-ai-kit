### 🎯 权威静态角色识别（v3，重大突破）
- **发现**：`window.Inputs.__metaclass.inputManagers` 持有游戏**实时的 InputManager 实例**（2 个键盘 + 1 个鼠标），每个实例有 `playerId` 字段 + 按键绑定
- **读取方法**（`STATIC_ROLES_JS`）：
  ```js
  const ims = window.Inputs.__metaclass.inputManagers;
  // 每个 m: m.playerId, m.forwardKey
  // KeyboardIM forwardKey===38(↑) => 'arrows'; ===87(W) => 'keyboard'
  // MouseIM => 'mouse'
  ```
- **优点**：
  - ✅ **静态**：直接读取游戏内部绑定，无需按键/移动探测
  - ✅ **刷新/回合切换后立即生效**（Lobby 状态即可读取）
  - ✅ **实时**：STATE_JS 每轮轮询内联读取，永远最新
  - ✅ **正确**：行为探测曾把 22489893 误判为 mouse，静态识别正确识别为 arrows
- **实现**：STATE_JS 内联读取 roles（每帧，静态方案）；tankctl.detect_roles() 用同一静态方案
- ⚠️ **纠正**：曾经记录"彻底移除行为探测/role_probe_loop"——**当前代码里仍在**：`monitor_server.role_probe_loop()`（`run()` 第 391 行启动的后台任务，`STATE_JS` 已含角色，它只做 5s 一次的变化日志、防噪）；`tankctl._probe_key` 也仍保留（注释标为"仅保留参考"）
- **健壮性修复**：STATE_JS 用 `typeof GameManager` 守卫，页面加载期返回 `no GameManager` 而非抛错

### 回合切换遮罩修复（between rounds / countdown 显示）
- **症状**：回合切换加载 + 开局倒计时的遮罩显示丢失
- **根因**：旧方案依赖 `ROUND_HOOK_JS` 注入事件监听，但：
  1. 页面刷新后 hook 丢失（只在 connect() 注入一次）
  2. 回调签名写错（`addRoundEventListener(cb, ctx)` 回调是 `(ctxt, gameId, evt, data)`，`data` 是对象不是事件名字符串）
- **修复**：改用**权威状态源** `GameModel.getState()`
  - `GameModel._STATES` 常量（全局可读）：`IN_ROUND="in round"`, `BETWEEN_ROUNDS="between rounds"`, `COUNTING_DOWN="counting down"`, `ENDED="ended"`
  - STATE_JS 每帧读取 `gc.model.getState()` 直接判断回合阶段
  - 100% 可靠，刷新/回合切换立即正确，无需事件 hook
- **验证**：endRound() 后 monitor `betweenRounds=True` 遮罩正确触发 ✓
- **附带发现**：`countDown()` 手动调用会因 UI 层缺资源报错，但 `getState()` 判断逻辑本身正确
- **鼠标输入本质**：事件驱动——只有鼠标移动/点击时写控制位，静止时保留最后状态
- **劫持控制**（仅本地局参考）：`hijack(tank_id, fwd,left,right,fire, duration, freq=50)` 高频注入压过输入事件
  - 验证：鼠标抖动干扰下仍控制鼠标坦克移动 13.6m ✓
  - ⚠️ **在线模式不可用**（直接 setter 不触发服务器同步 → 回弹）。在线用 `set_input()`
- **⚠️ 事故教训**：GWT 编译对象的方法**不可 hook/替换恢复**（会损坏输入链路导致游戏卡死）。必须用外部高频注入，不篡改游戏内部方法

### 击杀卡顿修复（重要）
- **症状**：坦克被击杀瞬间监控镜头卡顿 ~0.5s
- **根因**：击杀瞬间被击杀坦克短暂从 getTanks() 移除 → 触发角色失效检测 → **同步执行 ~1.3s 的角色重探测**（4 次 CDP 采样 + 2 次按键探测）阻塞了状态轮询 → 画面停滞
- **修复**：
  1. 角色探测移到后台任务 `role_probe_loop()`（不阻塞 poll）
  2. 防抖：tank 集合变化需连续 2 次采样确认才触发重探测（击杀后坦克快速复活，避免误触发）
  3. stale 标记：检测到变化只打标记，后台慢慢处理
- **验证**：击杀瞬间 WS 消息间隔稳定 0.060-0.063s，无卡顿 ✓

### 监控可视化 60fps 优化
- **症状**：监控画面刷新频率低（实测 ~33fps）
- **根因（Windows 平台）**：`asyncio.sleep` 受系统时钟 tick（15.6ms）限制，`sleep(0.016)` 实际睡 30.7ms → 频率被压到 ~33fps
- **修复**：monitor_server.py 启动时调用 `ctypes.windll.winmm.timeBeginPeriod(1)` 提升 Windows 定时器分辨率到 1ms
- **配套**：poll_loop 用动态补偿 `sleep(0.016 - elapsed)`；serve_state 事件驱动推送（Event 唤醒，不再轮询）
- **验证**：两个实例均达 60fps（16.7ms/17.2ms）✓

### 持续自杀脚本（loop_suicide.py）— 多角色 + 在线支持
- **用途**：观战/数据采集——所有可控角色在对局中存活时自动自杀，循环往复
- **多角色支持**：读取 `window.Inputs.__metaclass.inputManagers`（2 键盘 + 1 鼠标 = 3 本地可控角色），对每个角色自杀
- **在线多人支持**：输入管理器只绑定本地玩家（`INPUT_TYPES`=keyboard/mouse/touch，`getAllInputSetIds`=`["WASDKeys","arrowKeys","mouse"]`），在线模式自动只操控本地坦克
- **核心逻辑**：
  1. 回合状态：`GameModel.getState()`（in round/between rounds/counting down）
  2. 存活检测：velocity>0 = 活；v=0 = 死（frozen corpse 留在 getTanks，isAlive 方法不存在）
  3. 自杀机制：**贴墙点射**（弹丸出膛 2.5m，贴墙反弹瞬间自伤，路径最短）
  4. 角色集合周期刷新（重生/新回合自动同步）
- **⚠️ 传送安全（防卡墙外）**：传送到**开放 tile 中心**（查 getTiles 可通行性），绝不传送到墙边固定坐标
- **验证**：3 角色连续 13+ 次自杀循环成功，无越界
- **用法**：`python scripts/loop_suicide.py [port] [--record out.jsonl] [--fps 20]`

### 录制数据压缩（CompressedRecorder）
- **原理**：地形（walls/maze/zones）只在回合切换时变化，**只在变化时写一次**（带 mv 版本号），其余帧只存动态数据（tanks/projectiles/collectibles/mines/scores/roles）
- **使用**：`--compress` 选项（recorder.py 和 loop_suicide.py 都支持）
- **解压回放**：playback_server 自动检测压缩格式，用 `CompressedRecorder.iter_expanded` 还原
- **验证**：196 帧只写 1 次 maze/walls，解压回放完整正确
- **优势**：文件小得多 + 地形独立便于诊断回合切换

- **用途**：双击启动带远程调试的 Edge 游戏窗口
- `python launch_cdp.py [port] [url]` — 默认 9222，tanktrouble.com/game
- **防冻结 flags**：--disable-backgrounding-occluded-windows、--disable-renderer-backgrounding、--disable-background-timer-throttling、--disable-features=msTabSleeping 等
- **自动聚焦窗口**：启动后 PowerShell AppActivate 将游戏窗口带到前台（Edge 会冻结不可见标签页导致游戏暂停）
- **验证**：9224 实例成功启动（Edg/154.0.4258.37）

### 浏览器冻结问题（重要）
- **现象**：游戏窗口最小化/被遮挡/后台时，Edge 自动冻结标签页 → 游戏暂停（用户有上百标签页，冻结更频繁）
- **原因**：Edge 节能模式 + 标签页睡眠，`visibility:hidden` 的页面被节流/冻结
- **缓解**：
  1. 游戏窗口保持前台/最大化（最有效）
  2. 用 launch_cdp.py 的防冻结 flags 启动
  3. Edge 设置 edge://settings/system 关闭"节能"和"页面睡眠"
  4. 之前遇到的"冻结"很可能就是这个，不是代码 bug

### 自杀脚本去传送 + 迷宫尺寸实时化（重要）
- **去传送**：默认禁用 SetPositionAndAngle（在线多人坐标归服务器，本地改无效）。`--allow-teleport` 保留为 no-op 兼容参数
- **迷宫尺寸实时读取**：迷宫每回合重新生成（尺寸会变），之前启动时读一次导致**距离变负数**。现在每次 suicide_once 实时读 getMaze 尺寸
- **负距离钳制**：max(0, dist)
- **高效自杀（正对墙+贴墙+开火）**：
  - 算最近墙 → 转向**正对墙**（物理转向 via setInputState，循环重试直到 facing 收敛；不再用 setRotation 直设——在线无效）
  - 驱动到 ~3m（弹丸出膛 2.5m，垂直撞墙反弹回自己）
  - **facing 未收敛就不开火**（避免弹丸射偏飞走），下轮重试（近墙 wall_dist≤6m 时容错开火）
  - 验证：连续 15 次全部 facing=OK 全部自杀成功
- **🏆 最近墙优化（含内部墙）**：用 `find_nearest_wall`（gameutils）从 maze tiles 构建**全部墙段**（外边界 + 内部墙），算点到线段最近距离 + 墙法线方向。选**最近的墙**（不再只选外墙）→ 弹丸路径最短，自杀更快
  - 验证：所有案例 `wall=nearest dist=5.0m`，多数 2-3s 完成
- **⚠️ 在线回弹**：在线模式服务器回弹控制，setRotation/forward 可能被覆盖。脚本自动重试转向，facing 未收敛则不 fire（避免射偏）
- **🔧 转向符号（实测修正，重要）**：此前 loop_suicide 用 `d>0→left` 与 pickup_mine/suicide_script 的 `diff>0→right` 相反。游戏源码 `_computeRotationSpeed` 显示 `left→负角速度`；实测（0.5s 按住）：**LEFT→drot=-1.6，RIGHT→drot=+1.9**。权威结论：**右转增大旋转值，左转减小**。所有脚本已统一为 `d>0→right`（tankctl.aim_at、loop_suicide、suicide_script、pickup_mine）

### 🎯 在线模式回弹根因 + setInputState 修复（重大）
- **症状**：在线模式下脚本自杀频繁回弹 + 开火无效；手动操作完全正常
- **根因分析**（rc.setInputState 源码）：
  - 在线模式坦克状态由**服务器权威**。脚本直接 `tank.setRotation/setForward/setFireDown` **只改本地字段，不触发 emitTankState** → 服务器不知道，每帧用权威状态覆盖回来 = 回弹；fire 服务器不认 = 开火无效
  - **手动操作正常**：键盘输入每帧经 InputManager → setInputState → setTankState → **emitTankState 发服务器** → 服务器认可
  - `setRotation`/`SetPositionAndAngle` 在线**完全无效**（服务器回弹，验证 rot 不变）
- **修复**：新增 `TankCtl.set_input(tank_id, fwd, back, left, right, fire, hold, freq)`，构造 `InputState.withState(pid, fwd, back, left, right, fire)` → `gc.setInputState`（与真实输入同路径）
- **验证（在线模式）**：
  - setInputState(left) → rot 正常物理旋转（4.7 rad/s）
  - setInputState(forward) → 坦克正常移动
  - setInputState(fire) → **开火有效**（能击杀）
  - 完整自杀 13 次全成功：转向→drive 贴墙 2.4-3.1m→facing=OK→开火
- **drive 前进贴墙**：分 0.5s 短段驱动，每段后重校准朝向（forward 会轻微偏转），避免 drive 后 misaligned
- **仅录制脚本**：`python scripts/record_only.py [port] [--out f] [--fps N] [--duration S] [--compress]`（不控制坦克，被动录制）
- **⚠️ 录制覆盖**：Recorder 默认**覆盖**文件（不追加），避免新旧混杂。追加用 `--append`

### 本地局自动开局 + 控制角色绑定（2026-10-02，重要）
- **用途**：把 §4 B2 里"自动开 Local 局"的 TODO 收口——一条命令完成 Menu → Lobby → 对局，并**解决程序化开局的致命坑**

### 9.1 数据源优先级：能读游戏内部状态就别探测
- **角色识别**：行为探测（按键看谁动）→ 失败。改为直接读 `window.Inputs.__metaclass.inputManagers`（游戏自己的输入绑定表）→ 完美
- **回合状态**：事件 hook（addRoundEventListener）→ 签名错+刷新失效。改为读 `GameModel.getState()`（权威状态机）→ 完美
- **经验**：GWT 游戏把关键状态都存在对象实例/常量上，**深挖对象图远比行为探测可靠**。方法：
  1. `Object.getOwnPropertyNames(Object.getPrototypeOf(obj))` 找方法
  2. `Object.keys(obj)` 找字段
  3. 全局类（如 `GameModel`、`InputManager`）通常暴露常量（`_STATES`/`_EVENTS`/`__fields`）

### 9.2 GWT 编译代码的坑
- **方法 hook/替换 = 危险**：`roundController.setInputState` 被 hook 后无法正确恢复（变 `[native code]`），导致整个输入链路损坏、游戏"卡死"
- **教训**：GWT 方法有闭包/元编程层，**不要 hook 替换游戏内部方法**。要控制坦克，直接**调用游戏自己的输入链路** `gc.setInputState(InputState.withState(...))`（与键盘同路径，在线也有效）；要压过鼠标输入可用高频注入（仅本地局）
- **`__class`/`__fields` 元数据**：GWT 实例通过 `__class.__fields` 暴露字段结构（如 `InputManager` 的 `playerId`、`KeyboardInputManager` 的 `forwardKey`），这是静态识别的金矿

### 9.3 坐标与单位
- `getX()/getY()` 返回**米**（1 tile = 10m，`Constants.MAZE_TILE_SIZE`）。现役监控前端不再用 `PPM=20`，而是用 `maze.w*10` 米推出**一个**缩放系数，同一系数同时画墙和坦克
  - ⚠️ 由此产生的历史 bug：`monitor_server.STATE_JS` 曾用 `T=200`（像素）生成墙段，而坦克坐标是米 → 墙被放大 20 倍、几乎全部画到画布外。现已改为 `T=10`，**整个快照统一为米/tile 单位**
- 坦克旋转累积值会很大（43、206 rad），渲染用 sin/cos 无需 wrap
- `forward_angle = tank_rot - π/2`；转向速率 ≈ 4.5 rad/s
- **转向符号**：`setRight` → 旋转值增大；`setLeft` → 减小（实测 LEFT→-1.6, RIGHT→+1.9 rad/0.5s）。`diff>0`（需要更大旋转值）用 right

### 9.4 坦克控制三档方案（注意在线/本地差异）
| 方案 | 可靠性 | 用途 | 在线多人？ |
|------|--------|------|-----------|
| `setInputState`（`TankCtl.set_input`，InputState.withState） | ✅ 唯一有效 | 常规控制（移动/转向/开火） | ✅ 服务器认可（与键盘同路径） |
| 坦克对象方法 setForward/setLeft/...（`_tank_do`/hijack） | ⚠️ 本地局可用 | 本地调试 | ❌ 只改本地字段 → 回弹/开火无效 |
| Box2D `SetPositionAndAngle` 传送 | ⚠️ 本地局可用 | 精确布置/复位 | ❌ 服务器覆盖坐标 |

### 9.5 监控服务器稳定性
- **阻塞 = 卡顿**：poll 循环里任何 >100ms 的同步操作（如角色重探测）都会让前端卡顿 → 重活放后台任务
- **刷新/断连恢复**：页面 reload 后 CDP WebSocket 失效，需自动重连（5s 冷却）
- **玩家 ID 会变**：死亡/重生/进出导致 playerId 变化 → 一切按 ID 缓存的映射（角色）要能自动刷新或每帧重读

### 9.6 多人房间玩家列表
- `getQueuedPlayerIds()`/`getAllPlayerIds()` **不清理已退出玩家**（幽灵残留）
- 用 `getActivePlayerIds()`（含死亡但未退出的玩家，其击杀仍在计分）
- **不要** `activeIds ∩ tankIds`（死亡玩家坦克会临时从 getTanks() 移除，导致比分看不到）
