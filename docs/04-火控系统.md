## 2026-08-26 火控合格里程碑

**结论：连续 30 回合全部有击杀，零自杀 → 火控合格。**
（v3 验证轮，`fire_strict_v3.jsonl`，18678 帧）

### 关键修复（本轮）
1. **Lead 移动目标预测** — `aim_and_fire` 两处 `lead=False` → `lead=True`：
   根治"移动目标 miss → 超时/自伤"。需传 `target_id` 读取目标速度。
2. **最短旅行选角** — `find_aim_angle_raycast` 从所有命中角中选
   `traveled` 最短者（bounces 1~4）。一并修复 `traveled` 字段此前恒为 0
   的 bug（`_raycast_path` 未累加相邻路径点距离）。
3. **path_hits_self 修正**（`cdp_tools/ballistics.py`）：
   - 原用固定圆 `radius=2.0`，但坦克是可旋转 3×4m 矩形（角顶 2.5m）
     + 弹丸半径 0.25m。
   - 多反弹"回程贴近射手"的路径，官方射线(零宽)与真实弹丸(有半径)在
     坦克转向/目标移动时存在约 1m 偏差，实测命中点在 2.7~2.8m 仍会自伤
     （round6/7/26 三例均为此自毙）。
   - 改为保守 `self_radius=4.0`（含真实弹道偏差余量；这也是
     `ballistics.path_hits_self` 的**代码默认值**——`ballistics.py` 自己的
     docstring 误写成 3.0，以代码为准），出膛段
     `skip=sr+0.2`。==> 消除 sweep-back 自杀。

### 验证结果（fire_strict_v3.jsonl）
- 30/30 回合各自在 3 分钟内击杀目标
- 0 自杀（`victT` 从未意外增加）
- 0 直射（所有开火均 `bounces>=1`）
- 无贴脸死锁（过近自动拉开/换位）
- 目标在死角/非基础弹的回合按"无解回合"跳过，不计入失败

## 2026-10-02 复验与调参（DSH 接手后）

### 背景
接手后修了几个已证实的判定缺陷（历史环境记录已从公开仓库移除），
因为改到了**已验证的选角逻辑**，按规矩重跑 30 回合验收。三次复跑与结论：

| 轮次 | 配置 | 结果 | 结论 |
|------|------|------|------|
| v4 | 命中判定改本地坐标系 + 预筛兜底全量扫描 | ❌ 第 2 回合**自伤** | 自伤防护不足 |
| v5 | 上面 + 自伤半径 `4.0+1.0×反弹数`(≤8) | ⚠️ 无自伤，但 **10 回合里 6 回合找不到角**（跳过率 60%，v3 仅 14%） | 防护过激，误杀可用角 |
| v6 | 自伤半径 `4.0+0.5×反弹数`(≤6) + 飞行上限 45m | ❌ 第 12 回合**自伤**（成功 11/30） | 仍不足；且改动了已验证的选角集合 |
| v7 | **恢复 v3 已验证配置** + 仅保留飞行上限 45m | ✅ **30/30 回合全部有击杀、无自伤**（`fire_strict_v7.jsonl`，28362 帧，41 个迷宫版本 ≈ 11 次无解跳过） | **合格 —— 基线已回归并重新盖章** |
| v8 | 炮口出膛建模，偏移**猜 2.0m** + 飞行上限 45m | ❌ 第 11 回合卡死：反复选中同一角度（44m / 2 反弹）打 181s 不中 | 方向错（见下） |
| v9 | 炮口出膛建模，偏移**实测 2.5m** | ❌ **同一张图、同一角度**（43m / 2 反弹）卡死 180s | 与 v8 同因；A/B 实验后**判定该建模不可用** |

> v7 的 41 个迷宫版本里约 11 次"无解回合"跳过（跳过率 ~27%，v3 为 ~14%）：
> 主要来自新增的 `max_traveled=45`（长路径一律不冒险）。跳过不计入失败，
> 但确实是"更保守"的代价，后续可用"炮口出膛建模"把可用角找回来。

### v4 自伤取证（离线解析录制，非推断）
`scripts/fire_strict_v4.jsonl`：攻击者 t=30.5s 开火（62m / 3 次反弹的长路径），
弹丸 `deadlyToOwner=True` 飞出 13.7m 后折返，距车体 12.7→3.7→**1.8m**，
t=32.6s 攻击者消失。即：**固定 4.0m 自伤检查放行的长路径，真实回程把自己打死了**。
（v6 的失败则是 24m 短路径，证据同上：预测净空 >4.5m、真实回程 ~2.7m。）

### 结论：默认配置回归 v3，改进项做成可选参数

`find_aim_angle_raycast` 新增**默认关闭**的调参（默认值 = v3 验收时的行为）：

| 参数 | 默认 | 作用 | 状态 |
|------|------|------|------|
| `max_traveled` | None | 限制弹丸实际飞行长度，超限即判"此处无解"；严格验收脚本用 45m | ✅ 只减风险 |
| `self_radius_slope` | 0.0 | 自伤半径 `4.0+slope×反弹数`；0.5 能多挡一类自伤但跳过率↑ | ⚠️ 未重新验收 |
| `rotated_hit_check` | False | 命中判定用坦克本地坐标系（救回斜置坦克上本可命中的角） | ⚠️ 未重新验收 |
| `exhaustive_fallback` | False | 预筛无解时再做一次全量权威扫描 | ⚠️ 未重新验收 |

**下一步（模型正确性改动，不是拍参数）**：弹道预测目前从**车体中心**出发
（`_raycast_path` 用 `getX/getY`），而真实弹丸从**炮口**出膛。
已实现为 `muzzle_offset` 参数（默认 0.0 = 现状），验收脚本加 `--muzzle <米>` 即可开对比轮次。

**炮口偏移实测（从 `fire_strict_v7.jsonl` 的 131 个出膛样本反推）**：

```
出生点 = 车体中心沿炮口方向前移  中位数 2.50 m（p10=p90=2.50），与炮管夹角中位数 0.0°
反推校验：弹速 18.0 m/s（与常数一致，说明反推可信）
反推公式：出生点 = 弹丸位置 − 速度 × timeAlive
```

即**炮口在车体中心正前方 2.50 m**。这个事实本身成立，但**把它当作 RayCast 起点是错的**：

### 判定实验（几秒钟的 A/B，而不是再烧一轮 30 回合）

在 v8/v9 卡死的那个实况上（attacker @(65.8, 6.5)，target @(65, 35)，in round）直接对比：

| `muzzle_offset` | 结果 |
|---|---|
| **0.0**（车体中心，当前默认） | `None` —— 正确判定"此处无解"，交给机动换位/跳过 |
| **2.5**（实测炮口偏移） | `38° / 2 反弹 / 43.3m / hit=True` —— **真实弹丸永远打不中的幻觉命中** |

**结论：把射线起点前移到炮口会让"命中目标"的判定变乐观**，在紧凑几何下批量产出
假命中（v8 用 2.0m、v9 用 2.5m 都复现同一角度）。因此：

* **中心出膛模型保持默认**（物理上近似，但在该场景下是**保守**的：它说"无解"）。
* `muzzle_offset` 保留为**默认关闭**的参数，并在文档里标注**已证伪**，不要再直接开。
* 若将来要做对，方向不是"挪起点"，而是**用真实弹道做离线标定**：拿录制里的
  （位置, 朝向, 弹丸真实轨迹）去逐条比对模型预测，先建立一个"每秒可跑几百次"的
  离线验证器，再决定改哪一项——**不要再直接用 30 回合验收当调参工具**（v8+v9 共烧掉
  约 40 分钟实机时间，而 A/B 只需几秒）。

**验收脚本自身的一个观察**：卡死那轮里，脚本在"补射未中 → 机动换位"后仍会再次选中
**完全相同**的角度并重复开火，直到超时。它作为"缺陷探测器"有效，但很费时间；
后续可加"本轮已失败角度黑名单 / 同角度失败 N 次强制换位"。
（另注：v9 的失败是在 v8 留下的**同一回合**上重入的，所以两次失败并非两个独立样本。）

### 10.4 官方弹道 + 自建命中层（2026-10-02，进行中）

见 `docs/10-激光武器与瞄准线.md` §10。要点：

* **弹道改用官方 p2 射线**（炮口 2.5m 起点、镜面反射；实测与真实弹丸残差 0.005m）；
* 官方**没有**身份/半径/提前量，命中层由我们自己加（`scripts/official_aim.py`）；
* 从 v7 真实录制标定出两条会改变现有实现的规则：
  **真实反弹可达 13 次**（旧 `bounces ≤ 4` 过滤过于保守）、
  **`deadlyToOwner` 在第一次反弹时才变 true**（直射弹不会自伤 → 自伤判定只看首次反弹之后的路径）。
