# TankTrouble Radioactive Fog（辐射雾/毒圈）技术文档

## 概述

Radioactive Fog（辐射雾，俗称毒圈）是 TankTrouble 在线多人模式中的缩圈机制。随对局时间推进，地图边缘逐步向内收缩形成安全区。接触辐射雾秒杀坦克，无视护盾（护盾仅反弹射弹）。所有实体一击必杀，无血量概念。此文档基于游戏引擎运行时逆向分析。

---

## 1. 数据结构

### Zone 对象（JavaScript 引擎层）

通过 `GameController.getZones()` 获取，单个 Zone 暴露以下方法：

| 方法 | 说明 |
|------|------|
| `getId()` | Zone 唯一 ID |
| `getType()` | Zone 类型 |
| `getTiles()` | 安全区 tile 数组 `[{x, y}, ...]` |
| `getB2DBody()` | Box2D 物理体（4 条边墙 Fixture） |
| `getFields()` | 动态字段，核心数据来源 |
| `update(dt)` | 每帧更新（驱动缩圈动画） |
| `getCorners()` | 角落顶点（实现中返回 undefined） |
| `done()` | Zone 是否已销毁 |

### `getFields()` 返回的字段

```json
{
  "_expansionTime": 5.234,        // 当前缩圈步长剩余时间（秒），从 ~10 倒计时到 0
  "_expansionSequence": [0,3,1,1,2,2,0,2,2,2,3,0,...],  // 缩圈方向序列（每步消耗一个元素）
  "_tileBounds": {                // 地图 tile 边界
    "minX": 0,
    "minY": 0,
    "maxX": 10,                    // 地图宽度-1（tile 索引）
    "maxY": 6                      // 地图高度-1（tile 索引）
  },
  "_expansionSide": 0,            // 当前活跃缩圈方向：0=右, 1=下, 2=左, 3=上, -1=步间等待
  "_expansionTilesRight": 2,      // 右边已消耗 tile 数（整数）
  "_expansionTilesBottom": 1,     // 下边已消耗 tile 数
  "_expansionTilesLeft": 0,       // 左边已消耗 tile 数
  "_expansionTilesTop": 0         // 上边已消耗 tile 数
}
```

### 安全区实时计算

```
当前安全区 (tile 坐标):
  left   = tileBounds.minX + expansionTilesLeft
  right  = tileBounds.maxX - expansionTilesRight
  top    = tileBounds.minY + expansionTilesTop
  bottom = tileBounds.maxY - expansionTilesBottom

平滑插值（当前步内的连续坐标）:
  frac = 1 - expansionTime / stepMaxTime   // 0→1
  活跃边的 consumed = max(0, integerCount - 1 + frac)
```

> ⚠️ **上半段（整数 tile 边界）才是现役代码实现的**：`gameutils.extract_storm_zones` /
> `get_storm_zones` 只输出整数 tile 边界（`expLeft/expTop/expRight/expBottom` + `side`）。
> 下面的 `frac` 平滑插值**没有实现**，属于早期的渲染参考公式。

### Box2D 物理结构

`getB2DBody()` 返回一个 Box2D `b2Body`，包含 **4 个 Fixture**，每个 Fixture 是一个矩形条（边墙）：

| Fixture | 形状（示例 10×7 tile 地图，200px/tile） | 作用 |
|---------|--------------------------------------|------|
| 上边墙 | `(-0.4,-0.4)→(100.4,-0.4)→(100.4,0)→(-0.4,0)` | 地图上边界 |
| 下边墙 | `(-0.4,70)→(100.4,70)→(100.4,70.4)→(-0.4,70.4)` | 地图下边界 |
| 左边墙 | `(-0.4,-0.4)→(0,-0.4)→(0,70.4)→(-0.4,70.4)` | 地图左边界 |
| 右边墙 | `(100,-0.4)→(100.4,-0.4)→(100.4,70.4)→(100,70.4)` | 地图右边界 |

每个 Fixture 的 `GetShape()` 返回 `b2PolygonShape`，顶点可通过 `m_vertices` 数组直接访问：

```javascript
var body = zone.getB2DBody();
var fix = body.GetFixtureList();
while (fix) {
    var shape = fix.GetShape();
    if (shape && shape.m_vertices) {
        // shape.m_vertices = [{x, y}, {x, y}, {x, y}, {x, y}]
        // 4 个顶点构成矩形条，坐标单位：世界米（÷PPM=20 得像素）
    }
    fix = fix.GetNext();
}
```

**注意**：边墙的坐标是**世界米**，不是 tile 索引。乘 `PPM=20` 得到世界像素坐标。

## 2. 缩圈机制

### 缩圈时间线

```
对局开始 → 约 30s 缓冲期 → 开始缩圈
                                   │
每步约 10s:                        │
  _expansionSide = 序列[0]          │ ← 从 _expansionSequence 取方向
  _expansionTilesXXX += 1           │ ← 对应方向 tile 计数+1
  _expansionTime 从 ~10 → 0        │ ← 动画倒计时
  当 _expansionTime → 0:           │
    _expansionSide = -1 (步间等待)  │
  短暂等待后:                       │
    取序列[1] 重复...               │
                                   ↓
最终安全区缩小到 2×2 tile 左右
```

### `_expansionSide` 方向映射

| 值 | 方向 | 影响边界 | 视觉表现 |
|----|------|---------|---------|
| 0 | 右 | `maxX` 减小 | 右边界向左移动 |
| 1 | 下 | `maxY` 减小 | 下边界向上移动 |
| 2 | 左 | `minX` 增大 | 左边界向右移动 |
| 3 | 上 | `minY` 增大 | 上边界向下移动 |
| -1 | 步间 | 无 | 边界静止，等待下一步 |

### 判定规则

游戏使用 Box2D 连续碰撞检测——安全区边墙（4 个 Fixture）随缩圈向内移动。判定条件为**坦克中心点越过边界**（非边缘接触），一旦越过即秒杀，无视护盾。护盾（ShieldUpgrade，type=2）仅反弹弹丸，辐射雾直接穿过。判定使用**连续浮点坐标**，边界在 tile 间逐步滑动时，中心点更靠近边界的玩家先死亡。游戏无血条，所有伤害一击必杀。

## 3. 消息格式（发包详解）

### 3.1 编码协议：schemapack + varuint

所有 C↔S 二进制消息使用 **schemapack** 编码。规则：

| 规则 | 说明 |
|------|------|
| 字节序 | **大端序** (Big-Endian) |
| 字段排序 | 按 key name **字典序**升序排列 |
| string | UTF-8，前缀 **varuint** 长度 |
| 数组 | 前缀 varuint 元素个数，然后依次编码每个元素 |
| bool | 1 字节 (0x00=false, 0x01=true) |
| float32 | 4 字节 IEEE 754 大端 |
| int8/uint8 | 1 字节 |
| varuint | LEB128 变长整数 |

**varuint (LEB128) 编码**：

```
每字节低 7 位 = 数据位
最高位 (0x80) = 1 表示后续还有字节, 0 表示结束
小端序（低位在前）

示例:
  0   → 0x00         (1 byte)
  127 → 0x7F         (1 byte)
  128 → 0x80 0x01    (2 bytes)
```

### 3.2 typeId=1 RoundState — 每帧广播（S→C）

每帧通过 WebSocket 二进制帧广播，包含 8 个子数组。与 Radioactive Fog 相关的是 `zoneStates[]`：

```
顶层结构:
  _typeId                    uint8     = 0x01
  roundState                 object
    ├─ tankStates[]          array     (略)
    ├─ projectileStates[]    array     (略)
    ├─ trapStates[]          array     (略)
    ├─ collectibleStates[]   array     (略)
    ├─ weaponStates[]        array     (略)
    ├─ upgradeStates[]       array     (略)
    ├─ counterStates[]       array     (略)
    └─ zoneStates[]          array     ← Radioactive Fog 数据
```

#### zoneStates[] 元素结构

每个 Zone 对象编码如下（字段按字典序排列）：

```
fieldsJSON                  string   // JSON: {"_expansionTime":5.23,...}
id                          string   // Zone 唯一 ID
tiles                       [{x:uint8, y:uint8}]  // 安全区 tile 数组
type                        uint8    // Zone 类型
```

**编码顺序**（字典序）：`fieldsJSON` → `id` → `tiles` → `type`

#### 完整字节流示例

假设一个 zoneState：`id="z1"`, `type=0`, `tiles=[{x:0,y:0}, {x:1,y:0}]`, `fieldsJSON` 包含 `_expansionTime` 等。

```
字节流:
  [zoneStates 数组长度 varuint]
  [元素 0:]
    [fieldsJSON string]:
      长度 varuint                                ← e.g. 0x2A (42 bytes)
      UTF-8 字节: {"_expansionTime":9.5,...}       ← 42 bytes
    [id string]:
      长度 varuint = 0x02
      字节: 0x7A 0x31                              ← "z1"
    [tiles 数组]:
      元素数 varuint = 0x02                        ← 2 tiles
      元素 0: uint8 x=0x00, uint8 y=0x00
      元素 1: uint8 x=0x01, uint8 y=0x00
    [type]:
      0x00                                         ← uint8 type=0
```

#### 修正包机制

tick 路径（60Hz）每帧通过 `_make_correction_round_state` 发送**修正包**，分帧广播弹丸等高频实体（`CORRECTION_MAX_PROJECTILES_PER_FRAME`），防止单帧数据过大。Zone 数据低频变化，完整包含在每帧修正包中。relay 路径设置 `_forceFullCorrection=True` 时触发全量修正。

### 3.3 typeId=12 ZoneDestroyed — 实体销毁（S→C）

Zone 被销毁时发送。通常在回合重置（`_restart_round_locked`）时触发。

```
字段（字典序排列）:
  _typeId      uint8   = 0x0C
  zoneId       string  // 被销毁的 Zone ID
```

**字节流示例**（zoneId="z1"）：

```
0x0C                    ← _typeId=12
0x02 0x7A 0x31          ← zoneId: varuint 长度=2, "z1"
```

总共 4 字节。这是服务端最精简的消息之一。

### 3.4 与其他消息的时序关系

回合开始时 Zone 相关消息的发送顺序（以 3 人局为例）：

```
typeId=30 RoundCreated       → 通知新回合
typeId=48 RequestMazeResult  → 迷宫数据
typeId=26 GameState          → 房间元数据 (含 scoreStates)
typeId=25 CountDown (3→2→1)  → 倒计时（Zone 尚未激活）
typeId=31 RoundStarted       → 回合正式开始
typeId=1  RoundState         → 每帧广播（zoneStates[0] 开始包含 Zone 数据）
         ... 缩圈持续 ...
typeId=12 ZoneDestroyed      → 回合结束，Zone 销毁
typeId=29 RoundEnded         → 结算
```

Zone 在 `RoundStarted` 之后首次出现在 `RoundState.zoneStates[]` 中，初始 `_expansionTiles*` 全为 0，`_expansionSide=-1`。约 30s 缓冲后开始缩圈。

### 3.5 server.py 中的生成路径

```
_make_correction_round_state(game)
  └─ 遍历 game.roundState.zoneStates
       └─ 每个 ZoneState 原样序列化到 zoneStates[]

send_zone_destroyed(game, zone_state)
  └─ 发送 typeId=12 ZoneDestroyed 消息
  └─ 触发时机: _restart_round_locked 清除所有实体时调用
```

来源：`messageschemas.js roundStateMessage` / `server.py _make_correction_round_state` / `server-re.py send_zone_destroyed`

## 3.6 fieldsJSON 详解

Zone 的 `fieldsJSON` 是一个 JSON 字符串，包含缩圈动画运行时状态。从引擎逆向得到的完整字段：

```json
{
  "_expansionTime": 5.234,
  "_expansionSequence": [0, 3, 1, 1, 2, 2, 0, 2, 2, 2, 3, 0, 0, 3, 3, 2, 1],
  "_tileBounds": {
    "minX": 0,
    "minY": 0,
    "maxX": 10,
    "maxY": 6
  },
  "_expansionSide": 0,
  "_expansionTilesRight": 2,
  "_expansionTilesBottom": 1,
  "_expansionTilesLeft": 0,
  "_expansionTilesTop": 0
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `_expansionTime` | float | 当前步剩余时间（秒），约 10→0 倒计时，驱动缩圈动画 |
| `_expansionSequence` | [int] | 缩圈方向序列，每个元素 0-3，按顺序消耗。长度覆盖全地图 |
| `_expansionSide` | int | 当前活跃方向：0=右 1=下 2=左 3=上, -1=步间等待 |
| `_expansionTilesRight` | int | 右边累计消耗 tile 数 |
| `_expansionTilesBottom` | int | 下边累计消耗 tile 数 |
| `_expansionTilesLeft` | int | 左边累计消耗 tile 数 |
| `_expansionTilesTop` | int | 上边累计消耗 tile 数 |
| `_tileBounds` | object | 地图 tile 边界 `{minX, minY, maxX, maxY}`，值为 tile 索引（含） |

**注意**：JSON 字符串在 schemapack 二进制包中以 `varuint(长度) + UTF-8字节` 编码，约占 150-300 字节（取决于 `_expansionSequence` 长度）。`_expansionSequence` 从 `createInitialZoneState` 预生成，客户端和服务端共享相同算法。

### 3.7 Zone type 枚举

`zoneState.type` 是 uint8，当前已知：

| type 值 | 含义 | 说明 |
|---------|------|------|
| 0 | Radioactive Fog | 风暴模式安全区缩圈，唯一已知的 Zone 类型 |

从 `messageschemas.js` 和 `server.py` 的结构来看，`type` 字段保留用于未来可能的多种 Zone 类型（如不同的缩圈模式），当前仅使用 `type=0`。

## 4. Tampermonkey 提取实现（历史参考）

> ⚠️ **本节是历史实现，不是现役代码**：仓库里**没有**任何 Tampermonkey 脚本
> （`tamtam_prod.user.js` 已不存在）。当前提取走 **CDP `Runtime.evaluate`**：
> `gameutils.STORM_ZONES_JS` 在页面里对 `gc.getZones()` 求值，`get_storm_zones()`
> 解析结果。下面的代码片段保留的是当年的提取思路，可作为 `Runtime.evaluate` 内联
> JS 的参考，但不要按它去找项目里的 .user.js 文件。

通过 GC（GameController）运行时接口提取，无需解析二进制协议：

```javascript
// 获取 Zones
var zones = gc.getZones();  // 返回 Zone 对象字典

for (var zk in zones) {
    var z = zones[zk];
    
    // 获取动态字段（含 expansionTime, expansionSide 等）
    var fields = z.getFields();
    // fields._tileBounds: {minX, maxX, minY, maxY}
    // fields._expansionSide: 0-3 或 -1
    // fields._expansionTilesRight/Left/Top/Bottom: 整数已消耗 tile 数
    // fields._expansionTime: 当前步剩余时间（秒）
    // fields._expansionSequence: [方向序列]
    
    // 获取 Box2D 物理顶点（连续坐标）
    var body = z.getB2DBody();
    var fix = body.GetFixtureList();
    while (fix) {
        var verts = fix.GetShape().m_vertices;  // [{x, y}, ...]
        fix = fix.GetNext();
    }
}
```

### 实时安全区渲染公式（历史，现役代码未实现插值）

> ⚠️ 现役提取器 `gameutils.extract_storm_zones` / `get_storm_zones` 用的是
> **整数 tile 边界**（`minX+expLeft` / `maxX-expRight` / `minY+expTop` / `maxY-expBottom`），
> **不做**下表的步内 `frac` 平滑插值。需要连续边界的调用方请自行按此公式补，
> 不要以为库里已经有。

```javascript
// 整数 tile 边界
var minX = tb.minX + fields._expansionTilesLeft;
var maxX = tb.maxX - fields._expansionTilesRight;
var minY = tb.minY + fields._expansionTilesTop;
var maxY = tb.maxY - fields._expansionTilesBottom;

// 平滑插值（当前步内）
var frac = 1 - fields._expansionTime / stepMaxTime;
var side = fields._expansionSide;

// 活跃方向加上插值进度，从 target-1 平滑到 target
if (side === 0) maxX = tb.maxX - Math.max(0, fields._expansionTilesRight - 1 + frac);
if (side === 1) maxY = tb.maxY - Math.max(0, fields._expansionTilesBottom - 1 + frac);
if (side === 2) minX = tb.minX + Math.max(0, fields._expansionTilesLeft - 1 + frac);
if (side === 3) minY = tb.minY + Math.max(0, fields._expansionTilesTop - 1 + frac);
```

### 坐标转换

```
世界像素 = tile 坐标 × 200
画布像素 = ox + 世界像素 × scale
```

其中 `ox`, `oy` 为居中偏移，`scale` 为画布缩放比。

> 注：`200 px/tile` 是**旧 Viewer 的像素渲染常量**。现役代码的坐标单位是**米**
> （`Constants.MAZE_TILE_SIZE = 10` 米/格），监控前端用 `maze.w*10` 米推出一个缩放系数，
> 墙与坦克共用该系数；`monitor_server.STATE_JS` 生成墙段时也用 `T=10`（米），不再是 200。

## 6. 已知限制

1. **`getCorners()` 返回 undefined** — 该方法的 JavaScript 绑定可能未实现或仅存在于服务端
2. **`_expansionSequence` 可完全耗尽** — 序列预生成每步缩圈方向（如 `[0,3,1,1,2,2,...]`），长度足够覆盖全地图。实测若双方存活足够久，序列会被完全消费，最终安全区面积缩到 0（全地图被辐射雾覆盖），无人生还。
3. **边墙坐标精度** — `m_vertices` 使用 Box2D 坐标系（世界米），需 × PPM 转换为像素
4. **缩圈判定** — 使用 Box2D 连续碰撞，判定区域平滑移动。接触即秒杀，**无视护盾**（护盾仅反弹射弹）

## 8. 长时间收缩与序列耗尽（2026-10-24 深入实测）

### 8.1 长时间追踪（`probe_storm_long.py`，4 回合，420s）

| 回合 | 毒圈出现 | 安全区缩至 | 结束方式 |
|---|---|---|---|
| 1 | t≈57s | 40 → 15 格 | 坦克全灭 |
| 2 | t≈148s | 40 → 12 格 | 坦克全灭 |
| 3 | t≈270s | 54 → 15 格 | 坦克全灭 |
| 4 | t≈404s | 54 → 36 格（采样结束） | — |

* 每步缩 **一整行/列**（不是一格），间隔 **10s**，与 `STORM_ZONE_EXPANSION_TIME` 一致
* 方向序列长度随地图变化：实测 **10 / 12 / 13 / 14 / 15** 步
* 采样到的方向序列（例）：`[-1,3,-1,1,-1,2,-1,0,...]`（-1=步间等待；0右/1下/2左/3上）

### 8.2 源码逻辑（`index-4YALVKHK.js` 中 Zone 子类 `update()`）

`js
if (this._expansionSide < 0) {
  this._expansionSide = this._expansionSequence[
      this._expansionTilesRight + this._expansionTilesBottom
      + this._expansionTilesLeft + this._expansionTilesTop];  // 用"已移除格数"作下标
  switch (this._expansionSide) { 0:Right++; 1:Bottom++; 2:Left++; 3:Top++; }
  this._rebuildTiles(); this.roundModel.changeZone(this.id);
}
if (this._expansionTime <= 0) { this._expansionSide = -1; this._expansionTime = 10; ... }
`

* 每 10s 消耗序列的**一个元素**，移除对应边的一整行/列
* **序列耗尽后** `_expansionSequence[idx] = undefined` → switch 不匹配 → 不再收缩；
  安全区停留在最后状态（定时器继续空转）

### 8.3 ★ "缩没了"会怎样：**安全区面积归零，全图被毒圈覆盖，所有坦克瞬间死亡**

抓到的完整序列（地图 10×5=50 格）：

`
序列 = [1,0,1,2,0,2,2,0,3,3,0,2,1]（长 13）
50 → 40 → 36 → 27 → 24 → 21 → 18 → 15 → 12 → 8 → 4 → 3 → 2 → 0
第 13 步后：安全区 2×0 = 0 格（整张图都是毒圈）
`

即 **服务端生成的序列长度恰好是把整张图缩光所需的步数**（10×5 图需 13 步）。
时间线：回合开始 60s 出毒圈 → 5s 生长 → 每 10s 一步 → **约 195s（3 分 15 秒）后全图覆盖**。

> **对 AI 的含义（重要）**：`_expansionSequence` 是**服务端下发的**，一出现就能读到 →
> **可以提前算出整局的最终安全区轨迹**，从而规划"提前卡位/终局站位"。
> 另外：全图覆盖时所有坦克同时死亡 → 回合以"无人存活"结束（**是否判胜需实测确认**，
> 这是"保证回合结束"的兜底机制）。

## 9. 2026-10-26 在线补测补充（状态接口视角）

> 背景：本轮为监控/GET 黑盒补测（docs/27 §4.4，自建受控在线房间，`online_keeper.py` 自动重建+陌生人即离+夹具监督）。

1. **`expansionTime` 两相/锯齿语义（本次实测确认）**：
   - 10 s 周期 = **等待相**（`_expansionTime` 10→5，`_expansionSide=-1`，整数安全区不动）
     + **主动相**（`_expansionTime` 5→0，`_expansionSide=seq[k-1]`，雾在该边连续推进）；
   - 步进（`expansionTiles` 目标 +1、`safeTile` 变化）发生在 **expT≈5**，到 0 后重置为 10；
   - 采样/像素验证时：early(8–9.8) 是等待相、late(1–2.5) 几何差仅 1–2.5m；判别 `safeSmooth` 要用
     **mid(4.0–5.2)**（几何差 4–5m）。
2. **接口字段 `zones[].safeSmooth` 已验证**（状态快照 v6.6b，仅活跃边插值）：
   与本文 §7 公式重算 maxdiff=0.0m；减每边贴图 bias 后 active 边残差 0.65m（vs 整数 safe 2.66m，16/16 更优）。
3. **回合结束时的 zone 行为**：在线回合在「最后 1 辆坦克死亡」后**同一采样内** `zones=[]`、
   `storm_active=false`、`phase=between rounds`；**不是** safeTile 逐渐归零。因此要观测本文 §8.3 的
   “全图覆盖”，需要“序列耗尽但回合尚未结束”的场景（本轮采样未拿到；仅消耗 6/14 步就被全灭提前结束）。
4. **胜负/比分**：`winner` 恒 null；本轮在线观察到 `scoresVict` 在死亡**同一采样** +1，
   与本地实测 ~2.9–3.0s 延迟不一致 → 在线语义待复核（本地训练仍按旧结论用 `scoresKill` + 延迟 `scoresVict`）。
5. **朝向像素验证方法坑**：在线皮肤+雾染色下，用“PCA 前后延伸不对称”判炮管正负会 180° 翻转；
   应以**最远饱和像素方向**为准（本轮 3 车/5 帧炮管误差中位 1.28°、车体 PCA 模 π 1.65°）。

## 10. 2026-10-27 全图覆盖终局实测（Classic）

1. **模式/窗口**（客户端 `Constants.GAME_MODE_INFO.ACTIVE_HOURS`，UTC）：
   - Classic / Last Tank Standing（mode 0）：`[0,1,2,4,5,6,8,9,10,12,13,14,16,17,18,20,21,22]`

   `gameModeName="Last Tank Standing"`；v6.7 新增字段）。

   **新建房间的第一局**，并保证第一局不提前全灭。
